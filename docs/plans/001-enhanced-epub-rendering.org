#+STATUS: Active

* Objective

Improve EPUB fidelity without weakening Shōsai's native reading experience or
mistaking text shaping for a complete HTML/CSS implementation.  ADR 001's first
gate compared an embedded ~wry~ webview with an expanded native renderer and
selected native on 2026-08-21.  Production work follows the native milestones
and preserves the recorded security, packaging, accessibility, and maintenance
boundaries.

* Current Baseline

- ~crates/shosai-core/src/epub/parser.rs~ reads container/OPF, spine, TOC,
  XHTML, and manifest resources.  Manifest resources are held eagerly in
  ~EpubContent.resources~ behind canonical read-only resource views.  Shared
  admission policy bounds archive input, entries, compression, aggregate bytes,
  XML, fonts, and image dimensions before resources reach presentation
  backends.  A canonical resolver validates archive names and same-book paths
  before parser or custom-protocol lookup.
- ~crates/shosai-core/src/epub/style.rs~ retains admitted stylesheets by
  canonical archive path and applies linked and inline styles in each chapter's
  document order.  The bounded native computed-style engine matches type,
  class, ID, structural-combinator, and supported functional-pseudo selectors;
  applies importance, specificity, source order, inheritance, inline styles,
  UA defaults, resolved lengths, and simple screen media rules; and lowers the
  supported property set into native block and inline presentation.  Per-resource
  and per-document byte/application limits plus rule, selector, component, and
  amplified processing-step budgets bound hostile CSS work.  Unsupported selectors,
  declarations, conditional rules, ~@import~, and named namespaces fail soft.
  Book-local ~@font-face~ rules feed bounded native shaping, and table parsing
  retains semantic captions, row groups, rows, cells, spans, and ordered nested
  content.  MathML remains a later milestone.
- ~crates/shosai-core/src/epub/render.rs~ converts XHTML to ~ContentNode~ and
  ~NodeStyle~.  Each ~EpubDoc~ parses that model once into an immutable chapter
  presentation shared by search, pagination, and continuous rendering.  Tables
  have a semantic model and readable native fallback; full table layout and
  MathML remain incomplete.
- ~crates/shosai-app/src/epub.rs~ owns heuristic pagination geometry, while
  ~app.rs~ derives paginated layout and directly creates Iced widgets for both
  reader modes from the shared chapter presentation.  Pagination runs on a
  blocking worker, rejects stale layout generations, and shares completed page
  storage across reader tabs.  Continuous layout measures chapter node ranges
  so scrolling, search, relayout, and mode changes retain chapter/character
  anchors instead of reparsing XHTML.  Shared admission checks image dimensions
  and estimated RGBA size, but backend-specific decode allocations remain a
  release boundary.  Ordinary paginated turns reuse ~epub_pages~, resolve
  bookmark state from the loaded bookmark cache, and queue/coalesce
  reading-state writes off the UI thread.
  The writer is flushed before shutdown.  Release app-action-to-present
  measurements are recorded in ADR 001; the remaining Iced widget rebuild is
  included in those measurements.  Internal same-book links resolve canonical
  chapter paths and bounded element-ID/legacy-name character offsets;
  user-activated HTTP(S) and mail links open in the system handler.
- A native route may use a text shaper such as ~cosmic-text~, but text shaping is
  not a CSS cascade, block/table layout engine, DOM, MathML renderer, or
  font-loading policy.

* Scope and Success Measures

In scope are EPUB reflowable content, tables, embedded fonts and CSS
~@font-face~, MathML, resource resolution, and regressions in existing reading
features.  Success means representative fixtures render predictably in both
reader modes, navigation/search/progress still work, and malformed or hostile
books fail safely without book-initiated network access.  User-activated
external links follow an explicit confirmation/allow policy.

** Spike A — ~wry~

Working evidence: [[file:../adr/001-epub-renderer.md][ADR 001: EPUB renderer]].

- [X] Render one chapter from bytes through a custom, non-network resource
  protocol; resolve XHTML/CSS/images/fonts relative to the OPF/chapter path.
- [X] Disable scripts, remote navigation, downloads, popups, and external
  resource fetching by default.  The macOS harness loads hostile remote
  CSS/image/font/frame/object/script references against a controlled loopback
  listener and fails unless it observes zero connections; unit tests cover the
  canonical navigation policy and prove the monitor detects a control
  connection.
- [X] Prototype theme/font-size injection, internal fragment links, reading
  position capture/restore, search highlighting, and continuous/paginated
  behavior.  A host-owned automated fixture applies dark-theme colors and a
  24 px reader font, follows a fragment link, inserts one exact search mark,
  produces multiple CSS columns, restores continuous flow, and retains a
  canonical chapter path, fragment, and chapter text offset rather than a
  browser scroll/pixel position.  The proof passes on Linux/X11; production
  multi-chapter integration and the remaining target matrix stay separate.
- [-] Prove that a child webview can be embedded and resized inside the Iced
  reader on each target, with defined focus/input/event routing, tab lifecycle,
  accessibility-tree behavior, and teardown.  Map browser positions back to
  stable logical EPUB locations rather than pixel/scroll offsets.  The macOS
  harness now creates and resizes the child from actual Iced placeholder bounds
  and has an automated parent-resize/child-update/focus/visibility/
  destroy-recreate/teardown proof, including an observed replacement size.
  A macOS overlay spike also confirms that the child ~WKWebView~ renders above
  an intersecting Iced modal, so overlay activation must hide the child.  Its
  automated proof hides only the current generation, holds and dismisses the
  modal, tracks changed placeholder bounds without re-showing the hidden child,
  then recreates it at the latest bounds and verifies the
  replacement size; a settled hide followed by an in-place show did not leave
  the Iced proof making progress and is not accepted as restoration evidence.
  A composited-window capture proof now supplements those logical checks with
  an exact-color host fixture.  On the rotated 2× macOS display it observed the
  same 4,771,834 marker pixels at backing-pixel bounds
  ~[841,1699]-[2522,4535]~ before hide and after recreate, and zero marker pixels
  while the Iced modal was active.  Capture dimensions were 3364×5954.  This
  proves visual restoration for that arrangement only; the 1× external,
  ordinary 2× external, and built-in Retina runs remain open, so the checklist
  is not complete.
  A second macOS proof collapses the placeholder until no usable bounds are
  reported, requires the current generation's Wry hide call to return ~Ok~,
  drops that child, restores the placeholder, and compares the replacement
  generation's Wry-reported logical size with the new measurement.  A third
  macOS proof moves the real parent from a 2× display to a 1× display, requires
  the changed Iced scale event to match scale queries before and after the
  bounds update, obtains a fresh Iced measurement, and compares the current Wry
  generation's reported logical size after applying those bounds.  This is
  logical-geometry evidence from one real display transition, not proof of
  visual or backing-pixel correctness.
  A macOS input proof now observes exact text and keydown events in a focused
  child DOM input.  After ~focus_parent~, it confirms through AppKit that the
  exact Iced/winit parent view is first responder, drains queued child keys, and
  observes a fresh key in Iced.  The public Wry handoff therefore works on the
  tested macOS host without the direct AppKit fallback.  A tab-state proof then
  completes two reader/alternate-tab round trips: it hides and destroys each
  current child, verifies the alternate Iced tree has no reader placeholder,
  remeasures and recreates a new generation, restores the same canonical
  chapter fragment, rejects stale-generation callbacks and IPC, and completes
  a fresh child-to-parent input handoff on all three reader activations.
  A macOS System Events snapshot finds one WebKit web area and the labeled DOM
  proof input, but no Iced application control in the same window accessibility
  tree.  The accessibility proof mode codifies child/input count, focus,
  removal, fresh-generation replacement, and Iced-control requirements and
  confirms that the focused child subtree disappears while away and returns
  exactly once in a fresh generation with focus.  It then fails because the
  surrounding Iced control remains absent.  This is a Gate 0 blocker, not
  positive end-to-end accessibility evidence.
  The Linux/X11 input diagnostic now retains early DOM-focus evidence and
  proves exact text entry and synchronous positive DOM-blur evidence in the
  child.  Wry selected the Iced parent XID on a live XWayland session; under
  Xvfb, a direct Xlib fallback selected and synchronously rechecked it.  Neither
  path delivered a subsequent untargeted XTest key to Iced.  An XI2 monitor saw
  the raw event while a second X11 client selecting core key events on the
  verified parent received nothing; a core key sent directly to that parent did
  reach Iced without pointer activation.  This proves directly addressed parent
  routing but leaves physical-key handoff unresolved.  The harness tracks
  mouse/touch activation throughout parent handoff and rejects a following key,
  so the pointer-click control exits nonzero instead of being mistaken for a
  successful handoff.
  A Linux/X11 clipboard proof enables Wry clipboard access only on a host-owned
  fixture.  Iced writes and reads back an exact parent token, which WebKit pastes
  exactly.  WebKit then copies an exact child token that a separate GTK process
  can read while the harness pumps GTK, but Iced's own synchronous X11 clipboard
  read returns no text after its selection conversion times out because the same
  UI thread must service WebKitGTK's response.  The proof intentionally exits
  nonzero on that result; bidirectional clipboard interoperability requires a
  custom asynchronous bridge or rejects this integration.
  Shortcut conflicts, Linux physical-key handoff, IME, the remaining
  visual-restoration display matrix, a viable Iced accessibility tree,
  screen-reader interaction, production-tab integration, production
  cross-chapter, and arbitrary character-offset locations remain open.
- [-] Record Linux WebKitGTK, Windows WebView2, and macOS WebKit runtime and
  packaging requirements, binary impact, accessibility behavior, process
  isolation, and ~wry~/platform license notices.  Existing evidence was enough
  to reject production Wry: native Wayland embedding is unavailable,
  WebKitGTK is absent from Linux packages, Linux clipboard interoperability is
  blocked, and macOS lacks one complete accessibility tree.  Full notices and
  package work are unnecessary unless a future ADR reopens the route.

** Spike B — Native renderer

- [X] Prototype a real computed-style boundary: parsed DOM, selector matching,
  specificity/source order, inheritance, UA defaults, and resolved lengths.
  The test-only ~native-computed-style~ fixture proves the bounded cascade before
  production ~ContentNode~ lowering without changing the current renderer.  ADR
  001 records supported selector/value semantics, the private
  ~lightningcss~/~parcel_selectors~ matcher boundary, licenses, and the remaining
  production selector/shaper integration, layout, font, accessibility,
  pagination, and MathML work.
- [X] Evaluate a maintained text shaper behind measurement/shaping interfaces;
  the test-only ~cosmic-text~ spike proves deterministic advanced shaping,
  bidi visual order with chapter-rebased logical source ranges and explicit
  unshaped separators, per-script Arabic/Hebrew fallback with valid glyphs,
  observable variable-weight shaping, italic face selection, and line
  measurement.  ADR 001 separately records that production layout integration,
  inline construction, tables, pagination, EPUB font-face,
  selection/accessibility, stable DOM locations, and MathML remain
  unimplemented; the bundled fixtures do not provide CJK or emoji glyph
  coverage.
- [X] Prototype a block-box and anonymous inline-root measurement boundary.
  The test-only Taffy spike proves block flow, adjoining positive margin
  collapse, ~display:none~, rich cosmic-text leaf measurement, stable source
  ranges plus explicit unshaped bidi separators, constrained image placeholders,
  and same-process repeatable geometry on each tested target.  The bounded
  bridge rejects min-content text queries and multi-paragraph inline leaves
  rather than approximating them.  Taffy is only a block-box engine: CSS inline
  construction/whitespace, explicit base direction, tables, fragmentation,
  selection/accessibility, cross-target numeric stability, and production
  caching remain separate work.
- [X] Prototype normalized native table geometry.  A redistribution-safe XHTML
  fixture proves explicit caption, row-group/header, ~rowspan~/~colspan~, nested
  link/image, measured-cell, and narrow-overflow evidence through Taffy's Grid
  implementation.  This is not a CSS table algorithm: browser intrinsic track
  sizing, anonymous table repair, collapsed borders, painting, accessibility,
  and pagination remain unimplemented.
- [X] Prototype bounded EPUB-local font loading.  A generated test fixture
  proves ~@font-face~ descriptor/source parsing, canonical stylesheet-relative
  resolution, local/remote/missing fallback rejection, TTF and CFF OTF
  admission, WOFF/WOFF2 table-directory preflight and output-bounded decoder
  callbacks, malformed/oversized rejection, unsupported descriptor fallback,
  newly loaded family validation, and same-family isolation between per-book
  cosmic-text databases.  This historical dev-only bridge did not bound Brotli or
  transformed-table scratch allocations and does not implement arbitrary
  CSS-family aliases, production resource budgets, cache lifecycle, complete
  descriptor matching, or hostile-font/parser hardening; M2a replaced it with
  the production admission boundary and retired the bridge.
- [X] Render the same MathML/mixed-script fixtures and identify whether
  maintained permissive dependencies can fill each missing component.  A
  bounded test-only adapter produces semantic geometry for a narrow
  Presentation MathML subset and readable fallback for invalid/unsupported
  elements, while shaping keeps the missing CJK glyph evidence visible.  No
  maintained permissive Rust dependency directly accepts Presentation MathML
  and emits native geometry; the active MIT ~katex-rs~ candidate is TeX-in and
  web-markup/virtual-DOM-out, so a native route still owns the MathML front end,
  OpenType MATH layout, scene integration, selection, and accessibility
  boundaries.

* Implementation Milestones

** M1 — CSS and Resource Correctness

- [X] For the native route, replace class-only ~StyleMap~ with selector matching,
  cascade, inheritance, inline style, relevant at-rules, and computed values in
  ~epub/style.rs~; add explicit supported-property documentation.  Production
  chapter lowering now consumes one document-scoped computed-style map, honors
  linked/inline stylesheet order and bounded screen media rules, and carries
  relative inline font sizes into native rendering and pagination.  Module docs
  list the exact selector/property surface and fail-soft exclusions.  CSS
  resource, selection, complexity, and matching budgets reject work beyond the
  configured admission boundary.
- [X] Resolve stylesheet ~@import~ and ~url(...)~ relative to each stylesheet,
  with cycle, depth, origin, and size limits.  Imports now retain owner-relative
  source order and media conditions while sharing per-document application and
  selected-byte budgets; cycles stop at the active edge and excessive nesting
  rejects the document.  Supported resource URLs are rewritten to canonical
  isolated-book URIs before the owning stylesheet path is discarded.

** M2a — Embedded Font Admission and Presentation Metadata

- [X] Parse family aliases, source lists, style, weight, and supported format
  descriptors; resolve only canonical in-archive sources and reject local,
  remote, data, query-bearing, and escaping sources.
- [X] Validate font signatures, compressed-container directories, decoded sfnt
  signature/table count, fontdb metadata admission, face count, encoded and
  decoded size, descriptor/source inspection, source-reference bytes, family
  name/list bytes, and aggregate per-book limits.  Admit decoded faces into a
  private database owned by each ~EpubDoc~, select chapter-scoped source and
  Unicode-caseless family fallback deterministically, and release the database
  when its book closes.
- [X] Test WOFF/WOFF2/TTF/OTF admission (including Apple ~true~ sfnt),
  missing/corrupt/mismatched fonts, bounded family metadata and diagnostics,
  decoded aliases, weight ranges, retained bold/italic synthesis requests,
  deterministic fallback, independent same-family faces across two live books,
  zero-valued deny-all limits, and release of one book without disturbing the
  other.

** M2b — Embedded Font Native Rendering

- [X] Shape, measure, and rasterize admitted bytes with one per-book font system;
  the production Iced 0.14 font loader is process-global and has no unload API,
  so the renderer uses private synthetic aliases and RGBA line images instead
  of global registration or leaked ~'static~ CSS aliases.
- [X] Make embedded face metrics drive pagination, remeasure page fragments in
  their final shaping context, and
  preserve link hit-testing, search highlights, logical source ranges, and
  readable system-font fallback when a face is absent, rejected, or cannot be
  rasterized within the per-book cache budget.
- [X] Verify visual format parity, alias-to-internal-family mapping, weight/style
  face matching and synthesis policy, same-alias isolation across open tabs,
  uncached glyph-image rasterization, bounded shaping requests and pagination
  chunks, per-paragraph direction, continued-quote widths, native-owned widget
  height, cache cleanup on close, and representative macOS/Linux renderer output.  The
  exact stack renders bounded nonempty RGBA for TTF, OTF, WOFF, and WOFF2 and
  passes the full workspace gate independently on macOS and Framework 16 Linux.

** M3 — Tables

- [X] Preserve ~table~, caption, row groups, rows, cells, headers, ~colspan~, and
  ~rowspan~ in the core/native model.  Production chapter parsing now retains
  explicit and implicit row groups, header/accessibility attributes, styled
  captions and cell text/links, nested image resources, shared search offsets,
  and a readable native row fallback instead of flattening tables to prose.
- [X] Define overflow behavior for tables wider than the viewport and ensure
  cells are not split into unusable fragments in paginated mode.  Production
  table fallbacks now use a horizontally scrollable, width-bounded surface;
  pagination groups complete row-span bands into one surface per actual page
  fragment, retains source offsets, accounts for the renderer's exact padding
  and spacing, and keeps an over-tall band intact rather than splitting cells.
- [X] Verify theme contrast and nested links/images in cells.  Reader links now
  use theme-specific contrast-safe colors in both rich and embedded-font text,
  header cells have a contrast-safe theme surface, and nested table resources
  continue through the shared link dispatch and book-local image cache paths.
- [ ] Expose table and header semantics to screen readers.  Iced 0.14 exposes no
  accessibility-tree/AccessKit API to this application, so this requires an
  upstream framework capability or upgrade rather than an untestable widget
  approximation.

** M4 — MathML

- [X] Define the bounded native MathML implementation and fallback; JavaScript,
  a webview, and CDN fetching are not acceptable implicit dependencies.
  Production chapter parsing now admits a 64-node, 16-level, 1,024-visible-byte
  Presentation MathML model for rows, tokens, fractions, roots, scripts,
  fences, matrices, and semantics.  Unsupported markup retains bounded readable
  source-order fallback; over-budget subtrees stop at a fixed omission label.
  Standalone native geometry now consumes that retained model directly for the
  supported subset and shares one bounded layout between pagination and Iced
  painting.  Unsupported, uncovered-glyph, overwide, and overheight expressions
  preserve the readable text path; highlighted native expressions retain their
  geometry and use the active theme highlight.  Search and source offsets remain
  fallback-based.
- [X] Support inline versus display math.  Production rendering retains MathML
  semantics independently of native admission, promotes supported and unsupported
  explicit display math without dropping enclosing links, and admits atomic
  inline geometry only when the shared pagination/painting check succeeds for the
  effective container bounds, direction, alignment, and glyph coverage.  RTL,
  justified, over-bound, over-three-line-height, and unsupported cases retain
  word-or-glyph-wrapped splittable fallback.  Local
  regressions also cover wrapped-page height, blockquote slicing, bounded mixed
  embedded-font flow, aggregate pagination work, table-cell display geometry,
  table search separators, and hit-tested pointer dispatch through the Iced
  widget shell.
  Packaged native-app validation on Apple Silicon/macOS and Framework 16 Linux
  verified inline/display layout, fallback bounds, and repeatable linked inline
  and promoted-display activation.
- [X] Test common operators, fractions, roots, scripts, matrices, annotations,
  malformed MathML, and books that declare MathML manifest properties.  The
  generated MathML fixture now verifies retained inline fractions alongside the
  existing display, operator, script, matrix, annotation, malformed, and manifest
  evidence; app regressions cover admitted atomic pagination, shared geometry,
  highlights, hit-tested link-message dispatch, and source offsets.  Packaged-app
  pointer activation remains part of native release validation.

** M5 — Reader Integration and Release

- [X] Preserve chapter/fragment navigation, TOC, search and highlighting,
  bookmarks, progress restoration, themes, font sizing, continuous/paginated
  modes, multiple documents, and keyboard controls.  Production chapter
  presentations now retain bounded decoded fragment anchors for visible body,
  empty, inline, and table-descendant elements in the shared search-offset
  coordinate space; canonical same- and cross-chapter links select those
  offsets in paginated and continuous modes.  The contents panel resolves nav
  and NCX references relative to their own resources, decodes each target once,
  preserves nested grouping entries, and uses the document's indexed canonical
  chapter lookup to map fragment targets to the same stable locations.  Books
  without a usable TOC retain chapter fallback.
- [X] Establish the shared parsed-chapter/layout cache and stable-location model
  before backend adapters so chapter switches and preference changes do not
  repeatedly parse every chapter.  ~EpubPresentation~ parses each admitted
  chapter once; tabs retain reference-counted paginated derivatives keyed by
  viewport and typography, and character offsets survive relayout and mode
  changes.
- [X] Keep warm page turns free of parsing, repagination, image/font decoding,
  and synchronous storage.  Debounce or asynchronously persist reading state,
  resolve bookmark status off the turn path, and precompute/prefetch adjacent
  native presentation where needed.  EPUB turns now select an existing page,
  update bookmark status from the in-memory list, and enqueue coalesced reading
  state persistence without producing background layout work; a regression
  retains the parsed presentation, paginated-page allocation, layout key,
  decoded image handles, and render generation across the turn.
- [X] Move backend-specific rendering into focused modules under
  ~crates/shosai-app/src/~ rather than expanding ~app.rs~ further; keep EPUB
  parsing/resource policy in ~shosai-core/src/epub/~.  Stable-location,
  search-result, TOC, bookmark, and warm page-turn navigation has moved to
  ~app/epub_navigation.rs~.  Image presentation caching plus paginated and
  continuous EPUB widget construction now live in ~app/epub_view.rs~; generic
  reader chrome and state/update ownership remain in ~app.rs~.
- [X] Add feature/build configuration and packaging changes only for the native
  implementation; document runtime prerequisites and attribution.  Release
  packages bundle PDFium and Inter with their licenses.  macOS release builds
  use the host Apple compiler and SDK with a macOS 13 deployment target, and
  package validation rejects newer or non-portable Mach-O load commands.
- [ ] Run the full workspace test suite and platform packaging smoke tests.

  user-activated external links obey the documented confirmation/allow policy.
  Native presentation has no script or network loader; explicit link activation
  allows only same-book targets plus HTTP(S) and mail handlers, while all other
  schemes remain inert.
- [ ] Corrupt/oversized resources degrade safely with actionable errors.
- [ ] Existing EPUB navigation, search, bookmarks, themes, progress, and both
  reading modes pass regression tests.
- [ ] Gate 0 page-turn, chapter-transition, and relayout p50/p95 budgets are met
  on reference hardware or an accepted variance is documented.  Warm page turns
  perform no synchronous storage or avoidable resource/layout recomputation;
  repeated chapter changes do not leak per-book resources.

* Risks and Mitigations

- Webviews add platform runtimes and a large attack surface: use a deny-by-default
  protocol/navigation policy and platform package smoke tests.
- A native CSS/layout engine can become an unbounded browser project: commit to a
  documented EPUB subset and stop if spike estimates exceed the ADR threshold.
- Fonts are untrusted parsable binaries: validate, bound, isolate per book, and
  track backend security updates.
- Pagination can invalidate saved positions: persist logical chapter/fragment or
  text anchors rather than backend pixel offsets, with migration/fallback.
- Math rendering and accessibility vary by backend: test semantics as well as
  appearance and provide readable fallback text.

* Explicit Non-Goals

- General-purpose web browsing, JavaScript execution, remote fonts/assets, or
  arbitrary external navigation inside the reader.
- Full browser-level HTML/CSS compatibility, scripting-heavy EPUBs, EPUB fixed
  layout, media overlays, audio/video, or DRM-protected EPUB.
- Replacing Iced for non-EPUB application UI.
- Treating ~cosmic-text~ alone as a CSS, table, pagination, or MathML engine.
