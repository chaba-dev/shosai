#+STATUS: Draft
#+AUTHOR: Shōsai contributors

* Objective

Improve EPUB fidelity without weakening Shōsai's native reading experience or
mistaking text shaping for a complete HTML/CSS implementation.  The first gate
is an ADR-backed technical spike comparing an embedded ~wry~ webview with an
expanded native renderer.  No production renderer work starts until that gate
has selected an approach and recorded its security, packaging, accessibility,
and maintenance consequences.

* Current Baseline

- ~crates/shosai-core/src/epub/parser.rs~ reads container/OPF, spine, TOC,
  XHTML, and manifest resources.  Manifest resources are held eagerly in
  ~EpubContent.resources~ without entry-count, compression-ratio, or
  aggregate-byte limits.  A shared canonical resolver now validates archive
  names and same-book paths before parser or custom-protocol lookup.
- ~crates/shosai-core/src/epub/style.rs~ uses ~lightningcss~, but extracts class
  tokens from serialized selectors into a small-property ~StyleMap~.  It does
  not implement selector matching, the cascade, inheritance, layout, or
  ~@font-face~.
- ~crates/shosai-core/src/epub/render.rs~ converts XHTML to ~ContentNode~ and
  ~NodeStyle~.  Tables and MathML have no fidelity-preserving model.
- ~crates/shosai-app/src/epub.rs~ owns heuristic pagination geometry, while
  ~app.rs~ reparses all chapters on layout refresh, decodes images without pixel
  limits, and directly creates Iced widgets for both reader modes.  Ordinary
  paginated turns reuse ~epub_pages~, resolve bookmark state from the loaded
  bookmark cache, and queue/coalesce reading-state writes off the UI thread.
  The writer is flushed before shutdown.  Release app-action-to-present
  measurements are recorded in ADR 001; the remaining Iced widget rebuild is
  included in those measurements.  Internal-link fragments are ignored;
  user-activated HTTP(S) and mail links open in the system handler.
- A native route may use a text shaper such as ~cosmic-text~, but text shaping is
  not a CSS cascade, block/table layout engine, DOM, MathML renderer, or
  font-loading policy.

* Scope and Success Measures

In scope are EPUB reflowable content, tables, embedded fonts and CSS
~@font-face~, MathML, resource resolution, and regressions in existing reading
features.  Success means representative fixtures render predictably in both
reader modes, navigation/search/progress still work, and malformed or hostile
books fail safely without book-initiated network access.  User-activated
external links follow an explicit confirmation/allow policy.

** Spike A — ~wry~

Working evidence: [[file:../adr/001-epub-renderer.md][ADR 001: EPUB renderer]].

- [X] Render one chapter from bytes through a custom, non-network resource
  protocol; resolve XHTML/CSS/images/fonts relative to the OPF/chapter path.
- [X] Disable scripts, remote navigation, downloads, popups, and external
  resource fetching by default.  The macOS harness loads hostile remote
  CSS/image/font/frame/object/script references against a controlled loopback
  listener and fails unless it observes zero connections; unit tests cover the
  canonical navigation policy and prove the monitor detects a control
  connection.
- [ ] Prototype theme/font-size injection, internal fragment links, reading
  position capture/restore, search highlighting, and continuous/paginated
  behavior.
- [ ] Prove that a child webview can be embedded and resized inside the Iced
  reader on each target, with defined focus/input/event routing, tab lifecycle,
  accessibility-tree behavior, and teardown.  Map browser positions back to
  stable logical EPUB locations rather than pixel/scroll offsets.  The macOS
  harness now creates and resizes the child from actual Iced placeholder bounds
  and has an automated parent-resize/child-update/focus/visibility/
  destroy-recreate/teardown proof, including an observed replacement size.
  A macOS overlay spike also confirms that the child ~WKWebView~ renders above
  an intersecting Iced modal, so overlay activation must hide the child.  Its
  automated proof hides only the current generation, holds and dismisses the
  modal, tracks changed placeholder bounds without re-showing the hidden child,
  then recreates it at the latest bounds and verifies the
  replacement size; a settled hide followed by an in-place show did not leave
  the Iced proof making progress and is not accepted as restoration evidence.
  A second macOS proof collapses the placeholder until no usable bounds are
  reported, requires the current generation's Wry hide call to return ~Ok~,
  drops that child, restores the placeholder, and compares the replacement
  generation's Wry-reported logical size with the new measurement.
  Focus is only a successful Wry method return, not proof of actual focus,
  visually correct restoration, or keyboard/IME routing; the cross-platform,
  accessibility, real-tab, routing, and logical-location portions remain open.
- [ ] Record Linux WebKitGTK, Windows WebView2, and macOS WebKit runtime and
  packaging requirements, binary impact, accessibility behavior, process
  isolation, and ~wry~/platform license notices.

** Spike B — Native renderer

- [X] Prototype a real computed-style boundary: parsed DOM, selector matching,
  specificity/source order, inheritance, UA defaults, and resolved lengths.
  The test-only ~native-computed-style~ fixture proves the bounded cascade before
  production ~ContentNode~ lowering without changing the current renderer.  ADR
  001 records supported selector/value semantics, the private
  ~lightningcss~/~parcel_selectors~ matcher boundary, licenses, and the remaining
  production selector/shaper integration, layout, font, accessibility,
  pagination, and MathML work.
- [X] Evaluate a maintained text shaper behind measurement/shaping interfaces;
  the test-only ~cosmic-text~ spike proves deterministic advanced shaping,
  bidi visual order with chapter-rebased logical source ranges and explicit
  unshaped separators, per-script Arabic/Hebrew fallback with valid glyphs,
  observable variable-weight shaping, italic face selection, and line
  measurement.  ADR 001 separately records that production layout integration,
  inline construction, tables, pagination, EPUB font-face,
  selection/accessibility, stable DOM locations, and MathML remain
  unimplemented; the bundled fixtures do not provide CJK or emoji glyph
  coverage.
- [X] Prototype a block-box and anonymous inline-root measurement boundary.
  The test-only Taffy spike proves block flow, adjoining positive margin
  collapse, ~display:none~, rich cosmic-text leaf measurement, stable source
  ranges plus explicit unshaped bidi separators, constrained image placeholders,
  and deterministic geometry.  Taffy is only a block-box engine: CSS inline
  construction/whitespace, explicit base direction, tables, fragmentation,
  selection/accessibility, and production caching remain separate work.
- [ ] Render the same table/font/MathML/mixed-script fixtures and identify
  whether maintained permissive dependencies can fill each missing component.
- [ ] Estimate implementation and long-term compatibility cost for the EPUB CSS
  subset, including accessibility and selection.

** Decision and Exit Criteria

- [ ] Add an ADR under ~docs/~ recording scores for fidelity, sandbox/security,
  accessibility, portability/packaging, performance, offline resource control,
  reader-feature integration, dependency licenses, and maintenance cost.
- [ ] Select ~wry~, native, or explicitly defer.  Include rejected alternatives
  and a rollback strategy; do not choose merely from visual screenshots.
- [ ] Gate passes only when all spike fixtures have recorded results, dependency
  licenses are compatible with Apache-2.0 distribution, and CI/package owners
  accept the platform requirements.

* Shared Foundation (After Gate 0)

- [ ] Replace unrestricted resource access with a read-only EPUB resource API
  carrying bytes, media type, and canonical path.  Add configurable per-entry
  input/archive, entry-count, compression-ratio, per-entry, and aggregate limits
  to resist decompression/resource bombs.  Also bound XML depth/text and decoded
  image dimensions/bytes before backend allocation.
- [ ] Separate chapter parsing/computed presentation from
  ~crates/shosai-app/src/app.rs~ so search, pagination, and both view modes use
  one cached chapter representation and stable locations.
- [ ] Define fallback behavior for unsupported CSS, fonts, and MathML, with
  diagnostics that identify the chapter/resource but do not abort the book.

* Implementation Milestones

** M1 — CSS and Resource Correctness

- [ ] For the native route, replace class-only ~StyleMap~ with selector matching,
  cascade, inheritance, inline style, relevant at-rules, and computed values in
  ~epub/style.rs~; add explicit supported-property documentation.
- [ ] For the webview route, preserve author CSS while injecting a narrowly
  scoped reader stylesheet; serve all book assets only through the custom
  protocol and retain the core resource-policy tests.
- [ ] Resolve stylesheet ~@import~ and ~url(...)~ relative to each stylesheet,
  with cycle, depth, origin, and size limits.

** M2 — Embedded Fonts and ~@font-face~

- [ ] Parse family, source list, style, weight, and supported format descriptors;
  resolve only in-archive sources and reject remote/data sources unless the ADR
  explicitly permits bounded data URLs.
- [ ] Validate font signatures and resource limits.  Register fonts per book,
  apply fallback deterministically, and release registrations when a book closes.
- [ ] Add tests for WOFF/WOFF2/TTF/OTF as supported by the selected backend,
  missing/corrupt fonts, synthetic bold/italic policy, and same-family clashes
  across two open books.

** M3 — Tables

- [ ] Preserve ~table~, caption, row groups, rows, cells, headers, ~colspan~, and
  ~rowspan~ in the core/native model, or verify equivalent webview semantics.
- [ ] Define overflow behavior for tables wider than the viewport and ensure
  cells are not split into unusable fragments in paginated mode.
- [ ] Verify theme contrast, nested content, links/images in cells, and screen
  reader/header semantics where the selected backend exposes them.

** M4 — MathML

- [ ] Decide in the ADR follow-up whether MathML is native, backend-provided, or
  rendered by a bundled permissively licensed engine; JavaScript/CDN fetching
  is not an acceptable implicit dependency.
- [ ] Support inline versus display math, fallback text for unsupported markup,
  scaling with reader font size, theme contrast, and pagination boundaries.
- [ ] Test common operators, fractions, roots, scripts, matrices, annotations,
  malformed MathML, and books that declare MathML manifest properties.

** M5 — Reader Integration and Release

- [ ] Preserve chapter/fragment navigation, TOC, search and highlighting,
  bookmarks, progress restoration, themes, font sizing, continuous/paginated
  modes, multiple documents, and keyboard controls in ~shosai-app/src/app.rs~.
- [ ] Establish the shared parsed-chapter/layout cache and stable-location model
  before backend adapters so chapter switches and preference changes do not
  repeatedly parse every chapter.
- [ ] Keep warm page turns free of parsing, repagination, image/font decoding,
  and synchronous storage.  Debounce or asynchronously persist reading state,
  resolve bookmark status off the turn path, and precompute/prefetch adjacent
  presentation where the selected backend needs it.
- [ ] Move backend-specific rendering into focused modules under
  ~crates/shosai-app/src/~ rather than expanding ~app.rs~ further; keep EPUB
  parsing/resource policy in ~shosai-core/src/epub/~.
- [ ] Add feature/build configuration and packaging changes only for the ADR's
  selected backend; document runtime prerequisites and attribution.
- [ ] Run the full workspace test suite and platform packaging smoke tests.

* Tests and Fixtures

- Extend ~crates/shosai-core/tests/epub_tests.rs~ and unit tests in
  ~epub/render.rs~ / ~epub/style.rs~ for parsing, resolution, cascade, and limits.
- Add generated, redistribution-safe EPUB fixtures under
  ~crates/shosai-core/tests/fixtures/~ with source/build scripts or clear
  provenance.  Keep each feature isolated plus one combined conformance book.
- Add app tests near the existing EPUB tests in ~crates/shosai-app/src/app.rs~
  for stable locations, pagination, links, image/font caches, and fallback.
- Add an instrumented page-turn benchmark or performance harness that separates
  input handling, state/persistence, widget/backend layout, and presentation;
  run controlled latency smoke tests on release builds and reference hardware.
- Add screenshot/golden tests only with controlled fonts/backend versions;
  otherwise use semantic layout assertions to avoid platform-noisy snapshots.

* Acceptance Criteria

- [ ] The renderer ADR is approved before M1 and its security/license gates pass.
- [ ] Fixture tables, embedded fonts, ~@font-face~, and MathML satisfy documented
  semantic and visual expectations on every supported platform.
- [ ] No book content triggers network access or script execution by default;
  user-activated external links obey the documented confirmation/allow policy.
- [ ] Corrupt/oversized resources degrade safely with actionable errors.
- [ ] Existing EPUB navigation, search, bookmarks, themes, progress, and both
  reading modes pass regression tests.
- [ ] Gate 0 page-turn, chapter-transition, and relayout p50/p95 budgets are met
  on reference hardware or an accepted variance is documented.  Warm page turns
  perform no synchronous storage or avoidable resource/layout recomputation;
  repeated chapter changes do not leak per-book resources.

* Risks and Mitigations

- Webviews add platform runtimes and a large attack surface: use a deny-by-default
  protocol/navigation policy and platform package smoke tests.
- A native CSS/layout engine can become an unbounded browser project: commit to a
  documented EPUB subset and stop if spike estimates exceed the ADR threshold.
- Fonts are untrusted parsable binaries: validate, bound, isolate per book, and
  track backend security updates.
- Pagination can invalidate saved positions: persist logical chapter/fragment or
  text anchors rather than backend pixel offsets, with migration/fallback.
- Math rendering and accessibility vary by backend: test semantics as well as
  appearance and provide readable fallback text.

* Explicit Non-Goals

- General-purpose web browsing, JavaScript execution, remote fonts/assets, or
  arbitrary external navigation inside the reader.
- Full browser-level HTML/CSS compatibility, scripting-heavy EPUBs, EPUB fixed
  layout, media overlays, audio/video, or DRM-protected EPUB.
- Replacing Iced for non-EPUB application UI.
- Treating ~cosmic-text~ alone as a CSS, table, pagination, or MathML engine.
