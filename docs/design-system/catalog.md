## Render the product components

Run `.agents/dev make design-system-catalog`, then `make design-system`. The viewer's CatalogSearch section displays the actual Flutter specimens generated by `test/shell/browse_test.dart` into `build/design-system-catalog/`. It does not recreate the components in HTML. The PNGs are disposable build outputs, not committed golden baselines.

The fixtures cover light/dark desktop, desktop at 200% text, portrait/landscape tablet, light/dark phone and Japanese phone at 200% text. They query a real installed SQLite database with deterministic fixture data, deliberately fail a refresh, navigate results and select the alternate edition through the rendered controls. The edition menu also covers one choice and scrolling to the last of 24 choices. The synthetic volumes, variant counts and alternate rights text test layout and selection, not actual source metadata. Separate fixtures show first use, updating and an unreadable catalog while personal search remains usable. Each capture checks painted text and layout for clipping. Core tests check Unicode author matching and composed filters. Source links use an injected adapter in tests; no live external browser is opened by the fixture.

## Coverage and remaining states

All five patterns are documented and rendered. Foundation token changes: zero. Their colors use `ShellPalette` and `ShosaiTokens`; typography uses the existing `shellEditorialStyle` and `shellInterfaceStyle` roles. Spacing and shape use `ShosaiTokens.space*`, `radiusSm`, `radiusMd` and `sizeTouchTarget`. Literal geometry is confined to composition: the 2:3 cover ratio, 40 px row covers, 136 px shelf cards, 112/128 px minimum phone/desktop category heights scaled with text, 152/220 px minimum category widths, 152/200 px detail covers and the edition dropdown's 560 px maximum width. Category artwork keeps the same grounds and ink in both themes without changing chrome. Eight known categories use the mock's compact editorial titles and order; their full source labels remain accessible. Identities and counts come only from installed metadata; absent catalogs from the mock are not advertised.

The catalog path was searched for repeated inline UI, near-duplicate controls, recurring literal values, missing states and future needs. Existing covers, buttons, shell and search-hit rendering are reused; no additional foundations are proposed. Acquisition specimens exercise Add, progress, cancellation after publication, existing-content success, explicit Read and failed-download retry in light and dark themes through the controller bridge seam; they are not live provider downloads. New-book success, cancellation before publication, destination loading/failure, link failure and keyboard focus are not separate viewer specimens. Storage tests exercise real local downloads and files, with protocol fixtures for provider uploads. The viewer uses generated covers, not a live fetched-cover failure specimen. No reading-length filter, summary, publication year or ownership badge is fabricated from absent metadata. The more-by-author shelf remains unimplemented; restoring Browse does not establish complete fidelity for every detail-page element in the mock.
