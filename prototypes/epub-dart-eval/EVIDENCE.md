# Phase C evidence — Dart EPUB vertical slice

Scope: the evaluation prototype in this directory. Measurements come from one
runner (`framework16`, Linux, software rasterization under Xvfb). Nothing here
is a production baseline, an architecture decision, or a claim of parity with
the Rust renderer.

## Reproduction

```sh
# fixtures (byte-identical check)
.agents/dev bash -lc 'cd prototypes/epub-dart-eval && python3 tool/generate_fixtures.py --check'

# correctness evidence
.agents/dev bash -lc 'cd prototypes/epub-dart-eval && flutter test'
.agents/dev bash -lc 'cd prototypes/epub-dart-eval/packages/shosai_epub && dart test'

# measurements (release bundle + Xvfb; writes artifacts/measurements/*.json)
.agents/dev bash -lc 'cd prototypes/epub-dart-eval && \
  SHOSAI_MEASURE_TRIALS=5 \
  SHOSAI_MEASURE_BOOKS="$PWD/fixtures/rich-chapter.epub,$PWD/fixtures/long-chapter.epub,$PWD/fixtures/long-chapter-stress.epub" \
  SHOSAI_MEASURE_SPINES=0,1,0 bash tool/measure.sh'
```

## Cross-check against the Rust implementation

`packages/shosai_epub/test/normalize_test.dart` ports production Rust assertions
from `crates/shosai-core/src/epub/render.rs` and
`crates/shosai-core/tests/epub_conformance_tests.rs`:

- canonical text for headings, lists and tables (`Quarter\tValue`,
  `First half\tQ1 link`, `Q2 chart`);
- anchor offsets for sections, inline spans, duplicate ids, empty markers,
  captions, rows and cells;
- MathML fallback strings (`root(x, 3)`, `x_1^2`, `π`, no `\pi`);
- rejection fixtures: malformed chapter markup, oversized SVG dimensions,
  duplicate archive entries;
- image alt handling (block-level alt is canonical; inline alt is not).

One ported case is asserted as a **deliberate deviation**: display-block MathML
inside a paragraph is not promoted, so its generated separators are absent
(`before (a)/(b) after tail` vs the Rust `before \n(a)/(b)\n after tail`).
Rust can have bugs; these tests reuse Rust's *expectations*, not its code.

## Correctness evidence (tests)

| Check | Result |
| --- | --- |
| Engine tests (`dart test`, 15) | pass |
| Prototype tests (`flutter test`, 39) | pass |
| Page placement is exactly-once over rendered scalars (multiset, so a duplicate cannot cancel a gap) | pass for rich, decoded-image, small-page split, bidi, long and stress chapters |
| The flow and the pages render exactly the scalars the normalized chapter should render, each exactly once (independent node-derived counts; a negative test proves the comparison rejects a duplicated and a dropped scalar) | pass for rich, decoded-image, small-page split, bidi, long and stress chapters; newlines are separators and excluded on both sides |
| Continuous windows paint every rendered scalar at least once | pass (window sweep over the flow) |
| Selection spanning a page boundary projects rects on both pages | pass |
| Copy excludes hidden image alt text but keeps the caption | pass |
| Blank placeholder rejected by the content detector | pass (`nonBackgroundPixels == 0`, `hasContent == false`) |
| Captures contain ink (content-aware) | pass for paginated, table, CJK/bidi, continuous+dark, selection, highlight, long chapter |
| Pointer-level hit testing through the rendered surface (drag selects the painted glyphs; tapping a painted link navigates to its anchor; continuous hit testing accounts for the centred column) | pass (`test/pointer_test.dart`) |
| Reopen restores the stored `(spine, scalar)` after a page turn | pass, **controller reconstruction with a shared store** — not a process-restart test |
| Mode/font-size/resize preserve the durable scalar | pass |
| Tile arithmetic contiguous, `boundaries[0] == 0`, ≤ 10,000 tiles | pass |

What the coverage checks do **not** establish: they compare the flow's own line
ranges against the page slices (plus an independent node-derived expectation of
*which* scalars are rendered). They do not prove that every glyph is
unclipped, and they cannot detect a range that is wrong in the same way on both
sides. Continuous coverage is a window sweep over flow coordinates, not a
pixel-level proof of the composited scroll surface.

## Measurements (release bundle, Xvfb, llvmpipe)

Source: `artifacts/measurements/measure-20260928T080623Z.json` — one complete
run, 5 trials per book, report written after every completed book. Each book is
measured with a fresh in-memory position store, so repeated runs start at the
same place; the report records `initial_spine`/`initial_scalar` per book.

Frame-timestamp latencies from the first harness revision were **not** usable as
presentation measurements (the engine's stored begin-frame timestamp is not a
completion or presentation clock, and one sample even reported less frame
latency than layout work). The harness reports two honest endpoints:
`state_latency_micros` (dispatch → the model state the operation produces) and
`verified_capture_micros` (dispatch → a content-verified capture, including the
capture round-trip). Neither is a physical-presentation measurement; the capture
endpoint is an upper bound whose additional latency beyond the state endpoint
comes from the verification path: a fixed 120 ms pump wait, the `toImage`
render, the ink analysis, and (when an output path is set) a PNG encode. For
warm navigation most of the ~200 ms figure is that path; for a cold open the
layout dominates instead. The capture endpoint is not comparable across
operations.

| Book (spine) | Canonical scalars | Pages / blocks / lines | Cold open (state / verified capture) | Warm page turn (state) | Relayout (state / layout work) | Mode switch |
| --- | ---: | --- | --- | --- | --- | --- |
| rich-chapter (0) | 729 | 1 spread / 26 / 34 | 363 ms / 586 ms | 3.6–4.6 ms (chapter transition; single spread) | 106–116 ms / 2.8–18.1 ms | 106 ms |
| long-chapter (1) | 102,977 | 26 / 111 / 2,751 | 108 ms / 335 ms (chapter 0) | 61–127 µs | 134–165 ms / 43–70 ms | 141 ms |
| long-chapter-stress (0) | 606,227 | 151 / 111 / 15,951 | 790 ms / 1,048 ms | 57–98 µs | 640–784 ms / 514–641 ms | 394 ms |

Content verification passed at every measured point (ink present in the
capture). Relayout `state` includes the 80 ms coalescing delay, so the layout
computation alone is the `layout_work_micros` column.

`long-chapter` opens on its small first chapter, so its cold-open numbers
describe that chapter; the 103k-scalar chapter is reached with an explicit spine
jump (53 ms state, 52 ms layout work).

An earlier run mixed layout-work values from a pre-font-plumbing revision with
newer state latencies (producing an impossible "132 ms including coalescing,
215 ms of layout work" pair); that table was superseded by the single-run table
above, and the older logs remain under `.amp/in/artifacts/epub-dart-eval/` as
the historical record. The current runs also use a fresh in-memory position
store, so the earlier "reopened at the previous run's position" variation is
gone (it had changed the measured chapter/pages).

Resident memory (MiB). `ProcessInfo.currentRss` is current resident memory and
`ProcessInfo.maxRss` is the process peak; neither is a retained-heap measurement
and no causal attribution to specific structures is claimed.

| Book | After first content | After navigation | Continuous mode | Peak (max RSS) |
| --- | ---: | ---: | ---: | ---: |
| rich-chapter | 256 MiB | 256 MiB | 268 MiB | 310 MiB |
| long-chapter (102,977 scalars) | 272 MiB | 294 MiB | 309 MiB | 365 MiB |
| long-chapter-stress (606,227 scalars) | 386 MiB | 389 MiB | 480 MiB | 539 MiB |

Interpretation, stated conservatively:

- Warm page turns are cheap because the chapter flow and its page composition
  are precomputed once per layout.
- Relayout is the dominant cost and it is UI-thread work: tens of milliseconds
  of layout computation for a 103k-scalar chapter and roughly half a second for
  the 606k stress case in this environment. The Rust baseline's relayout budgets
  (18–22 ms p50 for a 16-chapter generated book) are not comparable: different
  machine, different fixture size, and the Rust numbers are Iced event-loop
  measurements. What is comparable is that Dart text layout cannot be moved off
  the UI thread (dart:ui is UI-thread bound), so a large relayout is a visible
  stall unless work is chunked or cached.
- Continuous mode's RSS snapshot is higher than the post-navigation snapshot
  (long: 294 MiB → 309 MiB, +4.9 %; stress: 389 MiB → 480 MiB, +23.2 %), but
  five font-size relayouts run between those two samples and there is no
  immediately-before-switch sample, so this run cannot attribute the growth to
  continuous mode. These RSS snapshots do not identify which allocations
  account for the growth or establish retained-heap growth. This remains an
  unresolved bounded-rendering concern (see "Open questions").
- The absolute numbers are software-rasterization numbers on one runner; they
  establish ordering and shape, not desktop-GPU budgets.

Inspected defects found and fixed during this work (kept as evidence that the
captures are load-bearing):

1. Table captions were painted twice (once by the caption slice, once by the row
   slice). Fixed by painting the caption only in its own slice.
2. Code blocks, math fallbacks and image alt text were mapped to canonical 0
   because their synthetic spans carried no canonical range; page starts and
   reopen positions were wrong. Fixed with node-derived canonical ranges.
3. Continuous mode painted a live background behind text painted with the
   previous palette, producing dark-on-dark after a theme change. Fixed by
   baking the palette into the layout.
4. A `RepaintBoundary` sized to the whole continuous flow was replaced by a
   viewport-sized painter overlay.
5. The generated PNG fixture had a corrupt IDAT CRC; the generator now builds
   the PNG itself.
6. A font-size/theme/viewport intent did not invalidate an already-running
   layout: the superseded completion could install a stale layout, clear
   `relayoutPending`, and let a readiness check pass on it. Fixed by bumping the
   layout revision at intent time (`controller.dart`), with a regression test
   that compares each settled layout's measured font size against the final one.
7. A nested table inside a cell rendered a rebuilt string (`A\\tB`) while its
   span claimed the node's canonical range (`A\\n\\tB`), so a hit on `B`
   addressed the separator. Fixed by rendering the exact canonical substring
   (trailing generated newlines trimmed with the range), with a hit-test
   regression on the glyph's own box.
8. A delayed clipboard completion cleared a newer selection. Fixed by only
   clearing the selection the copy was started from, with a delayed-clipboard
   regression test.
9. The measurement report failed to encode because a warm-navigation sample
   stored a Dart record instead of scalar fields; the last two runs produced
   only logs. Fixed, and `measure.sh` now passes `SHOSAI_MEASURE_SPINES`
   through. A later review also found the evidence table mixed layout-work
   values from a different revision; the table above is now generated from one
   complete run.

## Open questions this slice does not resolve

- **Retained-heap attribution.** RSS is not retained memory. A VM-service heap
  profile or a separate isolate is needed to say whether the continuous-mode and
  stress-case growth is retained layout or another allocation.
- **Physical presentation timing.** No presented-frame measurement was made; the
  harness reports state-change and verified-capture endpoints only.
- **Canonical-stream parity.** The MathML block-promotion deviation means the
  canonical stream is not yet identical to the Rust `search_text()` order for
  that case. This is recorded as an incomplete gate, not as a passing one.
- **Over-tall table rows.** Placed clipped and counted, not split at line
  boundaries. The Rust implementation splits rows; the prototype does not.
- **Layout on the UI thread.** No isolate strategy exists for `dart:ui` text
  layout. A hybrid (Rust normalization + Flutter layout) does not remove this;
  it only moves normalization off the UI thread.
- **Real-world CSS.** Only the fixture corpus and one generated rich chapter
  were exercised; no licensed book corpus was read.
- **Fonts.** WOFF/WOFF2 and emoji are unsupported; Hebrew/Arabic needed
  prototype-only host faces.
