## Generated EPUB font fixtures

`epub/book-a.{ttf,otf,woff,woff2}`, `epub/book-b.ttf` and
`epub/other-family.ttf` are generated by
`generate_epub_font_fixtures.py`
(`dcf135e196e627293fb871e1782b6e3ab3a5dedf394578140d363bc688169bb5`) with the
pinned toolchain in `requirements-epub-font-fixtures.txt`
(`fonttools==4.63.0`, `brotli==1.2.0`, `zopfli==0.4.3`).

**Regeneration is byte-identical** with that toolchain plus a fixed
`SOURCE_DATE_EPOCH`:

```sh
python3 -m venv .venv
.venv/bin/pip install -r crates/shosai-app/tests/fonts/requirements-epub-font-fixtures.txt
SOURCE_DATE_EPOCH=315532800 .venv/bin/python \
  crates/shosai-app/tests/fonts/generate_epub_font_fixtures.py
```

`SOURCE_DATE_EPOCH=315532800` is 1980-01-01T00:00:00Z, the `head.created` and
`head.modified` value the committed fixtures carry. Without it `fontTools` stamps
the current time into `head`, which is the only difference: every other table
compiles identically. The script does not set the epoch itself, so a regeneration
that is meant to reproduce the committed bytes has to set it (recorded here
rather than changed, because pinning it in the script would change nothing until
the fixtures are regenerated, and regenerating them changes the conformance
`SHA256SUMS` and every hash that cites them).
