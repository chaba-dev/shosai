= RFD 4 Phase 2 evidence

Phase 2 implements and measures the packaged highlighting feasibility slice. It
does not convert simulator or automated evidence into a manual accessibility or
physical-lifecycle claim.

Android packages `libshosai_flutter_bridge.so` and the pinned
chromium/7999 PDFium arm64 artifact in the APK. PDFium is resolved by soname in
Android's package namespace rather than by interpreting the Android runtime
executable as a desktop installation path. Both downloaded PDFium archives and
the Rust bridge build are produced by the checked-in host build scripts.

== Measurement protocol

Run:

----
make measure-flutter-m2 DEVICE=<flutter-device-id> OUTPUT=<evidence.json>
----

The profile harness performs five warmups and 50 measured samples. A synchronous
full-scene diagnostic round trip isolates generated bridge transfer and Dart DTO
materialization from Rust document extraction and layout. Selection timing uses
Flutter's build interval because the RFD boundary ends when the overlay is
submitted; raster work is reported by Flutter but is not added to that
pipelined boundary. Static page content is behind a repaint boundary and the
dynamic painter draws only annotation and selection overlays.

Resource evidence discards five complete open/render/release warmup cycles and
records RSS after 20 further cycles. The retained-growth decision compares the
median of the first and final five-sample windows with a 1 MiB tolerance for
allocator and page-accounting noise. Raw samples and the ordinary least-squares
slope remain in each JSON record. The logical resource checks additionally
assert that document, raster, selection, and cancellation handles release
successfully.

The Android profile APK is 64 MiB and the Linux profile bundle is 60 MiB. These
are build-artifact observations, not the RFD's installed-release-payload or
Flutter-over-native binary-size measurements. The fixture RSS is evidence for
the packaged feasibility slice, not the representative large-document ceiling.
Startup, installed release size, large-document steady RSS, full EPUB navigation
budgets, and comparison with the Iced reference therefore remain unclaimed.

== Accessibility, lifecycle, and visual evidence

Widget and controller regressions cover compact, medium, and expanded layouts;
safe areas and rotation; 200% text scaling; semantics and focus order; non-color
selection indication; lifecycle draining; process restoration; missing and
inaccessible locators; memory pressure; and renderer recovery. The physical
Pixel profile run verifies that the packaged PDF and EPUB bridge path and local
selection interaction execute on Android hardware. Its captured phone rendering
shows an aligned selected range and action surface without page-raster damage.

These checks do not replace the required manual run. TalkBack explore-by-touch,
real touch target confirmation, focus after an actual background/resume cycle,
and platform contrast/reduced-motion checks remain open on Android. VoiceOver,
rotor order, physical touch/orientation, and lifecycle recovery remain open on
each claimed Apple device. Missing files and revoked document-provider
capabilities also require a real provider rather than a path-only fixture.

== Exit assessment

The packaged Flutter/Rust highlighting slice works end to end for PDF and EPUB
on Linux and one physical Android device, and its scoped performance gates pass.
That satisfies the M2 go/no-go evidence for continuing the Flutter migration.
It does not make iOS, Windows, or the deferred manual accessibility, lifecycle,
startup, large-document, and release-size checks pass; those remain explicit
target-specific work and may not be inferred from Android or simulator results.
