= RFD 0004 implementation checklist

Implements link:README.adoc[RFD 4: Cross-platform Flutter frontend].

== Purpose

Build Shōsai as one Dart and Flutter application for desktop, phone, and
tablet: Dart document engines and a Dart application core under the Flutter
presentation, with no native bridge of the project's own. Keep web viable
through the bindings' browser builds or an explicit service adapter rather
than assuming native libraries work in a browser.

== Current baseline

As of 2026-10-21, after the Iced application and CBZ support were removed:

* `flutter/` is the application. `flutter/packages/shosai_epub` is the Dart
EPUB engine and serves paginated chapters, navigation and selection behind the
reader (adopted 2026-09-28, slices 2 to 5 merged). The library, reader chrome,
PDF reader, annotations, bookmarks, reading state and search reach the Rust
core through `flutter_rust_bridge` (`flutter/rust_builder`,
`flutter/lib/src/rust`).
* `crates/shosai-core` still owns PDF rendering through `pdfium-render`, the
SQLite store (`sqlx`, eleven tables, ordered migrations), library and import,
bookmarks, reading state, annotations and anchors, and search; its EPUB
modules are the retained fallback renderer the Dart engine's routing gate falls
back to. `crates/shosai-flutter-bridge` is the generated boundary.
* M0 to M2 are complete and were measured on that Rust boundary; their records
(link:PHASE-0.adoc[Phase 0], link:PHASE-1.adoc[Phase 1],
link:PHASE-2.adoc[Phase 2]) stay as evidence. M3.1 delivered the library slice
on it.
* The application is unreleased. Development databases, persisted anchors and
internal APIs may be reset or replaced rather than carrying temporary
compatibility machinery; no development data is deleted without an explicit
reset decision.

== Delivery rules

* The application is Dart only (RFD 4, Decisions, 2026-10-21). Build nothing
new in Rust; port behaviour from the Rust core with its tests, then delete the
crate. A Rust leaf plugin needs its own measured justification.
* Replace the core behind the retained UI in stacked slices (M3.0) before the
reader by format (M3.2) builds on it. A slice names the gates it closes and
the gates it leaves open; merging a slice is delivery, not acceptance.
* Preserve behavior while replacing a module. Do not simultaneously redesign a
domain contract and its Flutter presentation without executable core tests.
* Iced is historical reference only; its removal is its own change (RFD 4,
Proposal).
* Keep policy and domain behavior in the application core package; leave
widgets, gestures, navigation, lifecycle, and platform capabilities in Flutter
adapters.
* Every native dependency must pass build, packaging, lifecycle, memory, and
license gates on each claimed target. Desktop success is not mobile evidence.
* Do not delay native delivery on web, push notifications, cloud sync, or all
operating systems shipping simultaneously.
* Set a phase `STATUS` to `IN-PROGRESS` when its first task begins and `DONE`
only after every task and its `Exit` gate are satisfied. Later phases may
start early only where the dependency notes in the RFD permit overlap.

== First-release outcomes

The outcomes in the RFD's "The first release" section (folded in from the
former RFD 7 on 2026-10-20). Each item is done when its "done when" criterion
holds on desktop, tablet, and phone, for both EPUB and PDF where the item
touches the reader. The milestones below deliver them.

=== 1. Every device

* [ ] Adaptive shell: sidebar and rail on desktop and tablet; bottom bar and
switcher on phone.
* [ ] Notes surface as docked panel, slide-over panel, and bottom sheet.
* [ ] Search as palette and as full screen.
* [ ] Platform acceptance runs on Linux, macOS, Windows, iPad, Android
tablet, iPhone, and Android phone.

=== 2. Any medium

* [ ] One location model (section, percent, page) for EPUB and PDF.
* [ ] Shared progress bar and location line.
* [ ] Shared themes, including a night theme for PDF pages.
* [ ] One size control: EPUB text size and PDF zoom.
* [ ] Two-page spreads by default for EPUB and PDF, with a one or two page
setting; one page where two do not fit.
* [ ] RFD 6 selection, highlights and notes in both formats.
* [ ] EPUB writing direction from the spine's page progression and CSS
`writing-mode`, including vertical Japanese text; horizontal when undeclared.
* [ ] PDF pages re-rendered at the current zoom and display density.

=== 3. Notes and search

Tracked in link:../0006/IMPLEMENTATION.adoc[RFD 6's checklist], phase 4.

=== 4. Open books

* [ ] Open, focus, switch, and close books from the sidebar, the phone cards
and the switcher.
* [ ] Restore open books and positions on start.

=== 5. Jumpable references

* [ ] Peek for EPUB hyperlinks and PDF link annotations and destinations.
* [ ] Go to and a back stack shared by references, search results, and notes.

The completed interaction slice keeps widgets on the Elm boundary documented in
link:../../docs/flutter-architecture.md[the Flutter architecture contract].
Rust exports grapheme, word, visual-line, bidi, and oriented-caret metadata;
Flutter dispatches typed pointer, keyboard, focus, and action messages without
re-entering layout during interaction. Native and widget regressions cover both
formats, mouse/touch ownership, keyboard-only operation, cancellation and stale
completion races, annotation reopen/update/delete, geometry bounds, compact
large-text action layout, responsive composition, visible focus, non-color
selection state, cross-platform announcement policy, lifecycle draining,
resource recovery, process restoration, and unavailable-locator retry.
Packaged Linux and physical Pixel evidence, measurement definitions, Apple
readiness, and remaining non-claims are recorded in
link:PHASE-2.adoc[the Phase 2 evidence record].
Changed-fingerprint recovery uses explicit version association rather than path
equality: quote-backed text anchors recover against the associated version,
while geometry-only PDF anchors become orphaned instead of being silently
misplaced. Complete per-target screen-reader, physical failure, and release
measurement matrices remain explicitly unclaimed and are tracked in M5.

The first relayout increment now recomputes PDF geometry at the active display
scale and EPUB geometry at the active viewport, font size, and display scale,
then atomically publishes the raster, selection surface, and resolved annotation
snapshot. Completer-controlled regressions cover superseded work at selection,
render, decode, and annotation-list boundaries, deterministic handle release,
queued layout changes during open, bounded/cancellable quote resolution, and
exact/recovered/ambiguous/orphaned presentation. This proves relayout for the
same fingerprint (unchanged document bytes). Durable collection and version
identities now extend recovery across changed bytes after explicit user
association. Bounded, cancellable source discovery never infers identity from a
path; association persistence has a defined acceptance boundary, and reopening
the target resolves text anchors against its current content.

*Exit*: highlighting works end to end in both formats on desktop and at least one
physical mobile platform, and failures on any unvalidated target are recorded
rather than inferred away.

=== M3.0 — Replace the Rust core with Dart

Status:: IN-PROGRESS

Decided 2026-10-21 (RFD 4, Decisions). Each slice is one reviewable PR
stacked on the previous one, lands behind the retained library and reader UI,
and keeps the M2 and M3.1 interaction, lifecycle, restoration and
accessibility coverage green.

* [ ] *PDF engine.* Add the Dart-owned PDFium binding (`pdfrx` as evaluated,
with its PDFium version and checksums pinned) behind a controller-owned PDF
engine adapter: open and admission, page size and count, rendering at the
active zoom and display density into bounded owned bitmaps with cancellation
and release, page text with character bounds and mapping status for the RFD 6
PDF selection adapter, links, outlines and internal destinations for
outcome 5, encryption and permission state. Record how document permissions
are enforced, or that they are not. Prove the fixture corpus and the M0 raster
budgets on Linux, macOS and a physical Android device. The reader's Rust PDF
path is replaced in this slice; `crates/shosai-core/src/pdf.rs` stays as the
store's text extractor (annotation anchors, search over stored text) until
the Records slice retires it with the rest of the core.
** [x] Slice 1 (2026-10-21): `pdfrx` 2.4.7 (`pdfrx_engine` 0.4.5,
`pdfium_dart` 0.2.5; PDFium `chromium/7811` fetched by the binding's build
hook, the XCFramework from `pdfium_flutter` 0.2.3 on Apple targets) behind
`flutter/lib/reader/pdf/`: `engine.dart` is the reader's contract,
`pdfrx_engine.dart` the production engine, `selection.dart` the port of the
retained selection snapshot (loose glyph boxes, bidi and orientation,
half-zones, rows, keyboard lines, grapheme snapping, U+FFFD mapping) and
`search.dart` the port of case-folded search. The reader controller opens,
renders, builds selection surfaces, searches and lists the outline through
it; the retained document handle stays open for the store. Permissions
decision: the engine reports `isEncrypted` and `allowsCopying` and the reader
does not enforce them; copy eligibility is text-mapping completeness, as
before. A document that needs a user password fails to open.
** [ ] Open gates: the binding's build hook pins the PDFium release but
verifies no checksum; links and destinations are exposed by the engine and
not yet navigable in the reader (outcome 5); the fixture corpus and the M0
raster budgets on macOS and a physical Android device; `flutter test` loads
PDFium from `SHOSAI_PDFIUM_LIBRARY` (the Nix shell) or `PDFIUM_PATH` because
it does not link native assets. The Rust core's `pdfium-render` initialises
PDFium before each call and destroys it after; where it and pdfrx load the same
image (one `SHOSAI_PDFIUM_LIBRARY` in tests, likely one `lib/libpdfium.so` in
the Linux bundle and the Android APK), a Rust PDF open tears PDFium down under
pdfrx and the next page load crashes. pdfrx loads a private copy of an
environment library; the packaged hosts are unproven until Removal.
* [ ] *Store.* Add the Dart SQLite binding (`sqlite3`; `drift` only if typed
queries and migration tooling justify its code generation) in the application
core package, with a single connection owner, ordered migrations written fresh
for the Dart schema (no migration of development databases), WAL, background
isolate access where the binding supports it, and process-death recovery.
Prove that the bundled SQLite library loads from the packaged Linux and macOS
hosts and the Android build.
Started 2026-10-21 in `flutter/packages/shosai_core`: one worker isolate
owns the only connection; ordered migrations stamp `user_version` and an
`application_id`, and refuse foreign or newer databases untouched; WAL with a
killed-writer recovery test. `package:sqlite3` 3.5.2 bundles SQLite 3.53.4
through its build hook (the newest release Flutter 3.41.5 resolves). The app
depends on the package and opens the store at launch. Open: the packaged-host
and Android load proofs.
* [ ] *Records.* Port library and import (referenced and private managed
copies, bounded archive preflight, cover extraction, deferred cleanup,
duplicate detection by content identity), open books and reading state,
bookmarks, annotations with layered anchors, resolution states and bounded
quote recovery, and search over book text, into the Dart core with the Rust
integration tests ported as Dart tests. Anchor exact, recovered, ambiguous and
orphaned behaviour across relayout and changed bytes matches the M2 evidence.
The EPUB engine's canonical-stream parity gate against the Rust stream is
retired with the Rust stream; the engine's own fixtures become the reference.
** [x] Core (2026-10-21): `flutter/packages/shosai_core` ports library and
import (referenced and managed copies, archive preflight, EPUB covers and PDF
first-page covers through the PDF engine, deferred deletion, content-hash
duplicates), reading state, bookmarks and reader settings keyed by content
hash, annotations (layered anchors, quote-v1, exact, recovered, ambiguous and
orphaned resolution, bounded quote recovery in isolate batches) and search
(full Unicode case folding, Unicode 15.1.0, linear matching with the Rust
limits), with the Rust integration tests ported as Dart tests.
** [x] Controllers (2026-10-21): the library and reader controllers read
records through `ShosaiRecords` (`flutter/lib/core/records.dart`); the app's
`ApplicationBridge` serves them from the Dart core and still delegates
documents to the Rust bridge. EPUB search runs in the Dart core; annotations
read EPUB chapter text from the retained canonical stream, which both
renderers' selection surfaces index, and PDF page text from the PDF engine.
** [ ] Open: documents opened from a file outside the library keep no
highlights (the Rust store keyed them by path); the Rust document session and
canonical stream remain until Removal; PDF search is still duplicated in
`flutter/lib/reader/pdf/search.dart`.
* [ ] *Removal.* Delete `crates/`, `Cargo.toml`, `Cargo.lock`,
`flutter/rust_builder`, `flutter/lib/src/rust`, the `flutter_rust_bridge`
and `ffigen` dependencies, the bridge codegen and `check-frb` Makefile
targets, the Rust format, lint, test and bridge-codegen CI jobs, the Rust
toolchain and `pdfium-binaries` from the Nix flake and the Windows CI job,
`scripts/generate-theme-tokens.py`'s Rust authority entries, and the
retained-renderer routing gate in the EPUB reader. Rewrite the Makefile's
`test`, `lint` and `fmt` targets around Flutter and the scripts.
* [ ] *Documents.* Update the Flutter architecture contract, the roadmap, the
design system's ownership notes, RFD 2, 3, 5 and 6 where they name the Rust
core, and record the slice reports in the Dart document stack evaluation plan.

*Exit*: the Dart core gate in the RFD passes; no Rust remains in the build,
the repository's checks or the packaged hosts, and M3.1's library slice and
M2's highlighting slice run on the Dart core with their coverage intact.

== Verification and acceptance

* Core behavior and engine contracts have deterministic Dart tests independent
of Flutter widgets.
* Flutter integration tests cover representative desktop, phone, and tablet
states plus mouse, keyboard, touch, lifecycle, and restoration.
* Every claimed format and platform passes malformed/oversized fixtures, bounded
memory behavior, native dependency loading, and package launch/open smoke tests.
* Accessibility validation covers screen readers, text scaling, contrast, touch
targets, focus order, keyboard-only use, orientation, and non-color state.
* Paths and platform capabilities remain device-local; stable IDs and logical
anchors survive relayout and synchronization boundaries.
* Credentials, note text, selected quotes, and reading history do not enter logs,
crash diagnostics, notification payloads, or lock screens by default.
