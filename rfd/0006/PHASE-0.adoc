= RFD 6 Phase 0 contracts and evidence

This document freezes the inputs to the first durable migration.  The types are
conceptual contracts, not a synchronization wire format or a commitment to the
eventual Rust and SQL names.  Changes to a numbered contract require a new
version and new golden vectors; existing records retain their original version.

== Interaction contract version 1

The shared state machine is ~idle -> selecting -> selected -> committing ->
idle~.  EPUB and PDF adapters expose only logical endpoints and display
geometry; they do not own actions or persistence.

[cols="1,3"]
|===
|Input |Required behavior

|Pointer
|Primary press on selectable text captures an anchor.  Movement updates the
focus from retained geometry, may reverse direction, and clamps at one EPUB
spine item or PDF page.  Release opens the action surface for a non-empty range.

|Keyboard
|A focused reader exposes the platform text-selection commands.  Shift plus a
direction key extends by grapheme, word, or visual line as requested while the
stored range remains in logical order.  The context-menu key or equivalent
opens the same action surface; Escape cancels it.

|Touch-ready endpoint
|The adapter accepts the same press/move/release stream and endpoint model as a
pointer.  Handles are presentation state and never enter an anchor.  Touch
gesture recognition and platform testing are required before touch is enabled;
version 1 does not claim touch-platform support.

|Cancellation
|Escape, a press outside the selection/action surface, tab close, document
replacement, or navigation outside the allowed resource clears temporary state
without writing.  Losing capture while dragging cancels.  A persistence error
returns to ~selected~ and reports the error instead of discarding the range.

|Navigation
|Relayout, scroll, zoom, and navigation inside the selected resource preserve
logical endpoints and recompute geometry.  Navigation to another spine item or
PDF page cancels an uncommitted selection.  Activating a saved annotation first
navigates to its resource, then resolves and focuses it.

|Action placement
|Place one shared action surface above the union of visible range rectangles,
otherwise below it, then clamp to the reader viewport.  For a range extending
offscreen, use the visible focus endpoint.  Keyboard invocation anchors to the
focused range rectangle.  The surface contains Copy when text is complete,
five named colors, Add note, and Cancel, in the same order for both formats.
|===

Selection endpoints are grapheme-safe.  Ranges are half-open and ordered in
logical text order regardless of drag direction.  Empty clicks do not create a
selection.  Drag processing performs no PDFium, SQLite, file, or asynchronous
wait on the UI thread.

== Anchor contract version 1

The common envelope contains an opaque portable UUID, a format tag, anchor
version ~1~, fingerprint algorithm/version and bytes, the original quote when
available, normalization profile ~shosai-quote-v1~, normalized exact/prefix/
suffix strings, and one format payload.

EPUB payloads contain the spine occurrence, canonical resource path, and a
half-open chapter range counted in Unicode scalar values.  PDF payloads contain
the zero-based page, a half-open PDFium character range when mapping is
complete, and ordered rectangles in canonical PDF user-space points.  Neither
payload contains pixels, zoom, viewport, pagination, widget, or local database
coordinates.  A geometry-only PDF payload marks text mapping incomplete and
omits quote selectors and copy capability.

All consumers reject unknown required contract versions without modifying the
record.  They may preserve unknown optional fields.  Fingerprint equality only
enables exact-anchor validation; it is not a portable book or record identity.
Recovery is bounded to the recorded spine resource or PDF page and returns
exactly one of ~exact~, ~recovered~, ~ambiguous~, or ~orphaned~.

=== Quote normalization profile ~shosai-quote-v1~

In order: normalize CRLF and CR to LF, discard U+00AD SOFT HYPHEN, normalize to
Unicode NFC, map every non-empty run of Unicode White_Space code points to one
U+0020 SPACE, and trim leading/trailing collapsed space from each exact/prefix/
suffix field.  Preserve case, punctuation, compatibility distinctions, and
visible hyphens.  Prefix and suffix are nearest-context-first slices of at most
32 Unicode scalar values and move inward to a Unicode extended-grapheme-cluster
boundary rather than splitting a cluster.  Original text is never reconstructed
from normalized text.

[cols="2,2,2"]
|===
|Purpose |Input code points |Expected normalized value

|Canonical equivalence |~Cafe\u0301~ |~Café~
|Line endings and whitespace |~ a\r\n\t b\u00a0c ~ |~a b c~
|Soft hyphen |~co\u00adoperate~ |~cooperate~
|Preserved distinctions |~Case—A-B! ﬁ~ |~Case—A-B! ﬁ~
|No case folding |~Résumé~ / ~résumé~ |Two unequal values
|Context bound |33 ASCII ~x~ values |32 ASCII ~x~ values nearest the quote
|Grapheme-safe context |31 ~x~ values followed by ~e\u0301~ |31 ~x~ values plus ~é~
|===

Offset conversions are explicit.  EPUB version 1 offsets and quote limits count
Unicode scalar values; PDF offsets count PDFium characters from the pinned
extractor; future CFI offsets count UTF-16 code units.  No API accepts an
unlabelled integer offset.

== Identity and lifecycle alignment with RFD 3

An annotation record has one immutable opaque UUID independent of path and
SQLite row ID.  ~created_at~ is immutable, ~modified_at~ changes for any user-
visible body, color, or anchor edit, and nullable ~deleted_at~ makes a normal
delete a hidden tombstone.  Import provenance identifies the source system and
stable source identifier when one exists; it is not record identity.  A local
book foreign key and path are associations only.

RFD 3 still owns portable book identity, device identity, revisions, conflict
resolution, outbox state, acknowledgements, and tombstone retention.  Phase 1
must leave those fields additive: annotation reads never require sync metadata,
deletion never hard-deletes a normal record, and no tombstone is compacted until
RFD 3 defines a measurable safe condition.  This is the narrow overlap needed
to avoid either RFD choosing the other's wire protocol.

== Selection spikes and budgets

The executable proofs are in ~crates/shosai-app/src/selection_spike.rs~ and the
native embedded-font geometry retained by
~crates/shosai-core/src/epub/native_text.rs~.  They establish:

* an image-widget point maps to a rendered PDF bitmap point, after which the
  existing PDFium crop/rotation-aware conversion maps it to PDF user space;
* pointer hit testing uses an owned row/endpoint snapshot and therefore cannot
  acquire PDFium's global lock during drag;
* Iced's painting paragraph returns character offsets across adjacent rich-text
  spans, while the custom native layout now retains the exact shaped cluster
  rectangles and scalar ranges that it paints;
* a reader endpoint is only ~(spine occurrence, chapter scalar)~, so selection
  crosses block widgets and visual page fragments in either direction while a
  different spine occurrence is rejected.

The Phase 0 ceiling is 65,536 selectable endpoints per EPUB layout request or
PDF page snapshot, 16,384 ordered rectangles in one persisted annotation, and
8 MiB of retained selection geometry per open document.  A quote or copied
selection is limited to 65,536 Unicode scalar values; normalized prefix and
suffix remain 32 each.  Exceeding an extraction ceiling disables selection for
that surface with an actionable message; it never silently truncates an anchor.

The hot-path target is at most 1 ms per endpoint hit on reference development
hardware, leaving most of a 16.7 ms frame for event dispatch and painting.  Run
the deterministic upper-bound probe with:

----
cargo test -p shosai-app retained_geometry_and_hot_path_fit_phase_zero_limits -- --nocapture
----

The command constructs 65,536 endpoints in 256 rows, accounts for vector
payload capacity, performs 10,000 distributed hits, reports elapsed time and
retained bytes, and fails if either the 1 ms/hit or 8 MiB bound is exceeded.
This models a dense PDF page and a maximal admitted EPUB native-text request;
Phase 2 must additionally measure PDFium extraction and Phase 3 must measure
relayout because neither operation is permitted on the drag hot path.

On 2026-09-02, the x86-64 Linux development profile completed 10,000 distributed
hits in 973 µs (0.0973 µs/hit) and retained 1,583,104 bytes.  This is a synthetic
upper-bound geometry measurement, not a claim about extraction or full-frame
latency.
