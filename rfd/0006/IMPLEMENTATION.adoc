= RFD 0006 implementation checklist

Implements link:README.adoc[RFD 6: Cross-format highlighting, notes and search].

Phases 0 through 4 deliver the first release. Phase 0 closes contracts and
technical risk before the database schema becomes durable. Phases 1 through 3
build the shared core and one Flutter vertical slice per format. Phase 4
integrates the common product experience and is the first-release gate. Phases
5 and 6 are independent post-MVP interoperability work. RFD 4 owns the
application core, the platform gate, and the retirement of the Iced reference
frontend; since 2026-10-21 the core is Dart (RFD 4, M3.0), so the Rust
locations named in Phase 1 record where the work was done and Phases 2 to 4
build on the Dart core.

== Phase 0 — Contracts and technical proof

Complete this phase before committing the first database migration.

=== Recorded product decisions

* [x] Select natural document boundaries for the first release: one EPUB spine
item across block/page fragments, or one PDF page.
* [x] Model highlights as independent annotations with an optional note.
Bookmarks keep their lifecycle; their notes become page notes (amended
2026-10-20).
* [x] Ship exact-version offsets and geometry plus bounded quote recovery first;
defer EPUB CFI behind the versioned anchor contract.
* [x] Keep PDF highlights in SQLite first, then add native import and
export-to-copy, with safe in-place write-back as a later explicit action.
* [x] Use versioned conservative quote normalization: NFC, collapsed whitespace,
ignored soft hyphens, preserved semantic distinctions, and bounded context.
* [x] Use role-specific visual channels and a theme-aware yellow, green, blue,
pink, and purple palette with deterministic saved-highlight overlap behavior.
* [x] Permit geometry-only PDF highlights for incomplete Unicode mappings with
copy/recovery disabled; do not include OCR or hidden EPUB fallback text.
* [x] Make the first schema sync-ready with portable IDs, versioned anchors and
fingerprints, lifecycle timestamps, tombstones, and import provenance while
deferring wire protocol and conflict rules to RFD 3.

=== Contracts and spikes

* [x] Define the shared interaction contract for pointer, keyboard, touch-ready
endpoint behavior, action-surface placement, cancellation, and navigation.
* [x] Define a versioned anchor and Unicode normalization contract with test
vectors before committing the first database migration.
* [x] Align portable record identity, modification, deletion, and tombstone
fields with RFD 3 without making synchronization part of the read path.
* [x] Prototype an Iced selectable PDF page widget that converts page-widget
coordinates to PDF user space and emits stable character endpoints.
* [x] Prototype hit testing for ordinary Iced EPUB rich text and custom native
embedded-font text using the exact layout that paints each block.
* [x] Prove reader-level EPUB selection across adjacent inline spans, block
widgets, and visual page fragments within one spine item.
* [x] Measure drag latency and retained geometry on representative large EPUB
chapters and dense PDF pages; set explicit cache and payload limits.

The versioned contracts, golden vectors, executable spikes, measurement command,
and resulting limits are recorded in link:PHASE-0.adoc[the Phase 0 evidence].
The Iced spikes stop here: they remain executable evidence for logical endpoints
and geometry, but production highlighting continues in core and Flutter.

== Phase 1 — Annotation core and persistence

* [x] Introduce a renderer-independent annotation domain type in
`shosai-core` with a portable record ID, content identity, lifecycle fields,
color, optional body, and versioned target anchor.
* [x] Add an EPUB anchor containing spine occurrence, canonical resource path,
chapter scalar range, quote context, and a versioned extension boundary.
* [x] Add a PDF anchor containing page index, ordered page-space geometry,
PDFium character range, and available quote context.
* [x] Specify deterministic exact, recovered, ambiguous, and orphaned
resolution outcomes. Never persist an automatic relocation from an
ambiguous match.
* [x] Add the development SQLite annotation schema and store with CRUD, per-book
listing, bounded values, and transaction tests. Because Shōsai is unreleased,
replace prerelease migrations when that produces a cleaner schema instead of
adding compatibility-only tables or dual writes.
* [x] Persist portable UUIDs, versioned fingerprints and anchors, original and
normalized quotes, import provenance, lifecycle timestamps, and hidden
tombstones while keeping paths and database book IDs device-local.
* [x] Implement and test version 1 normalization, grapheme-safe context
extraction, and explicit offset conversions.

== Phase 2 — PDF Flutter selection vertical slice

* [ ] Extract bounded PDF page text, mapping status, character endpoints, and
ordered page-space geometry once per visible page.
* [ ] Expose the owned PDF selection snapshot through the controller-owned
PDF engine adapter and verify pointer movement in Flutter does not call the
PDFium binding, reopen the document, or acquire its global lock.
* [ ] Render temporary and saved PDF overlays in continuous, single-page, and
spread modes across manual, fit-width, and fit-page zoom.
* [ ] Preserve logical range order and correct page-space geometry for
multiline, bidirectional, ligature, cropped, and rotated text.
* [ ] Permit geometry-only highlights for incomplete Unicode mappings while
disabling copy and quote recovery; explain pages without a text layer.
* [ ] Verify equivalent mouse, keyboard, and touch endpoint behavior plus
screen-reader semantics on the RFD 4 platform matrix.

== Phase 3 — EPUB Flutter selection vertical slice

* [ ] Expose grapheme-safe logical hit testing from the renderer-neutral EPUB
layout/scene chosen by RFD 4, using the same geometry Flutter paints.
** EPUB layout is Dart/Flutter-owned as of 2026-09-28
(link:../../docs/dart-document-stack-evaluation-plan.md[decision record]); the adapter must derive logical ranges and display geometry from
the same Flutter layout. The anchor model is unchanged; the annotation store
is the Dart core's (RFD 4, M3.0).
* [ ] Coordinate drag selection across inline spans, block widgets, and visual
page fragments within one spine item, stopping at the spine boundary.
* [ ] Render temporary and saved EPUB highlights in continuous and paginated
modes without changing pagination geometry.
* [ ] Preserve logical ranges across font-size, line-spacing, theme, viewport,
and reading-mode relayout.
* [ ] Test left-to-right, right-to-left, mixed-direction, combining-mark, emoji
ZWJ, CJK, ligature, and multiline fixtures.
* [ ] Exclude hidden image alternative text and fallback strings as independent
selection targets while retaining visibly presented text.
* [ ] Verify responsive desktop, phone, and tablet layouts, touch handles,
keyboard extension, focus order, and screen-reader semantics.

== Phase 4 — Shared annotation experience and first release

* [ ] Load annotations outside the document-open critical path and preserve
active-tab isolation when switching or closing reader tabs.
* [ ] Add selection and annotation commands to the application core's
effect surface; PDF extraction lives in the Dart PDF engine, and the anchor
schema, normalization, resolution states and annotation store in the Dart
application core (RFD 4, M3.0), format-neutral, with the engines supplying
canonical text and geometry.
* [ ] Provide the shared selection action surface for copy, named color choice,
optional note creation, and cancellation with equivalent behavior in both
formats.
* [x] Add an annotation list with navigate, recolor, note edit, and delete
behavior alongside, but independent from, bookmarks. The reader's Notes panel
shows highlights and notes as note cards; bookmarks list under Contents.
* [x] Page notes and book notes in the annotation store: a location anchor or
none, same identity, timestamps, tombstones and provenance as highlights.
Notes across the library are listed from the store alone, books most
recently read first.
* [x] Bookmark notes become page notes: a migration moves each bookmark's note
to a page note at the bookmark's place, and bookmarks keep no note. The reader
writes, edits, opens and deletes page notes and book notes in its Notes panel.
* [ ] Notes surface scoped to this book or all books, grouped by place; open a
note at its anchor. This book is done: the reader's Notes panel groups book
notes first, then each section's notes in reading order, and edits notes in
place. All books is done in the shell's Notes place, which lists every book's
notes, most recently read first, and opens a note's book at its place. Still
to come: the panel's This book / All books switch.
* [ ] Library-wide search over book text and notes from every screen, scoped
and filtered as the RFD describes, with a return point for Back. The search
palette is done: Ctrl+K or ⌘K, `/` and the Search place open it over the
library or the reader, with This book / All books and Everything / Text /
Notes, and a hit opens its book there. Back is done in the reader: a jump
from search, a note, a bookmark, a link or the contents shows a Back pill
that returns to where the jump left from (Alt+← or ⌘[ too), jumps stack, and
three page turns or Stay here close it. A book opened at a hit goes back to
where it was last read. Still to come: the current match marked on the page.
* [ ] Keep bookmarks and highlights as independent domain records without
compatibility adapters for the unreleased Iced UI or development schema.
* [ ] Reopen unchanged documents and verify exact anchors survive restart,
EPUB font-size/theme/viewport relayout, and PDF zoom/DPI changes.
* [ ] Exercise bounded recovery against inserted, deleted, repeated, and
normalized text and verify ambiguous/orphaned records remain visible.
* [ ] Apply the named theme palette and role-specific selection, search, link,
and saved-highlight channels, including deterministic overlap behavior.
* [ ] Provide keyboard-reachable highlight actions, visible focus, non-color
indication, theme contrast, and screen-reader labels for annotation controls.
* [ ] Preserve logical selection order and grapheme-safe user endpoints for
bidirectional and complex Unicode text.
* [ ] Bound copied quote/context and exclude it from logs and diagnostics.
* [ ] Verify database migration behavior, process interruption, unavailable
files, malformed anchors, documents changed in place, and tab lifecycle.
* [ ] Run `make lint`, targeted core-package and Flutter tests,
`make test-app`, and `make check-rfds`.

Phases 0 through 4 are complete only when all first-release acceptance criteria
below pass on RFD 4's selected desktop and physical-device platform matrix.

== Phase 5 — Native PDF interoperability (post-MVP)

* [ ] After the first release, import native PDF text-markup annotations and
export Shōsai annotations to a new user-selected PDF copy.
* [ ] Preserve import provenance and deduplicate repeated imports without
changing the SQLite source-of-truth model.
* [ ] Add explicit in-place PDF write-back only after encrypted, signed,
read-only, externally modified, duplicate, conflict, and atomic-save cases are
covered; never write back automatically.
* [ ] Define a versioned portable serialization only when required by RFD 3 or
the portability decision; local SQLite remains authoritative until then.

== Phase 6 — EPUB CFI interoperability (post-MVP)

* [ ] Preserve source text-boundary identity through EPUB parsing and
presentation without changing existing scalar anchors.
* [ ] Add EPUB CFI range generation and resolution, including package/spine
indirection, escaping, assertions, and malformed-input limits.
* [ ] Add explicit Unicode-scalar to UTF-16 conversion and range tests across
elements, supplementary code points, and grapheme clusters.
* [ ] Add CFI as an additional selector in the versioned EPUB anchor and prove
existing annotations require no migration.

== First-release acceptance criteria

* EPUB and PDF expose the same create, preview, recolor, note, navigate, and
delete experience within the approved selection scope.
* Saved highlights remain attached across restart and presentation-only layout
changes; unresolved anchors are reported rather than silently moved.
* Pointer drag does no blocking PDFium or SQLite work on the UI thread.
* Search, links, bookmarks, pagination, zoom, continuous mode, tabs, and
document-open responsiveness retain their existing behavior.
* The persisted schema and domain API do not depend on viewport coordinates,
database-local IDs as portable identity, or one renderer's text offset model.
* The feature passes RFD 4's desktop plus physical-device input, lifecycle,
memory, and accessibility gate before it is treated as proof of mobile support.
