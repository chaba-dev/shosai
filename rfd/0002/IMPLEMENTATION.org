#+TITLE: RFD 0002 implementation checklist
#+STARTUP: showall

Implements [[file:README.adoc][RFD 2: Additional ebook formats]].

* Objective

Add plain text/Markdown, DjVu, FB2, unencrypted MOBI/AZW3, and CBR through a
small format-extensibility seam.  Each format is an independently shippable work
package with dependency/license approval, bounded parsing, fixtures, reader and
library integration, and explicit acceptance criteria.  DRM circumvention is
outside the project.

* Current Baseline and Prerequisites

- ~BookFormat~, extension recognition, database strings, metadata/cover dispatch,
  and directory import are hard-coded in ~crates/shosai-core/src/library.rs~.
- ~OpenDocument~, file-dialog filters, extension dispatch, page counts, reader
  behavior, and several per-format branches are hard-coded in
  ~crates/shosai-app/src/app.rs~.
- ~crates/shosai-core/src/document.rs~ is raster-page-oriented.  EPUB instead
  exposes chapters and ~ContentNode~; CBZ exposes archive images.  A single
  forced ~Document~ implementation is therefore not the prerequisite.
- New work requires representative, legally redistributable fixtures and a
  dependency review recording crate/library license, transitive/native code,
  maintenance status, security history, target support, and packaging impact.

* Gate 0 — Minimum Format Extensibility Seam

:END:

Build only the seam needed to remove duplicated recognition/import/open logic;
do not design a plugin ABI.

** Core Registry

- [ ] Move format identity and capabilities to a focused module such as
  ~crates/shosai-core/src/format.rs~: stable database key, extensions, display
  name, media kind (~raster_pages~, ~reflowable~, ~archive_images~), and support
  status.  Preserve existing ~pdf~/~epub~/~cbz~ database values.
- [ ] Centralize case-insensitive path detection and supported-extension lists.
  Where extensions overlap or containers are ambiguous, allow bounded signature
  probing and return a typed unsupported/corrupt error.
- [ ] Define an import adapter returning normalized title, author, optional cover,
  and format; route ~Library::import_file~ and directory scans through it instead
  of ~extract_metadata_and_cover~'s match.
- [ ] Keep format implementations as explicit Rust modules in ~shosai-core~.
  Avoid dynamic loading, object hierarchies that erase useful format behavior,
  and a premature universal document model.

** App Factory

- [ ] Add one document-opening factory that returns reader state by media kind;
  derive file-dialog filters from the core registry and replace extension matches
  in ~crates/shosai-app/src/app.rs~.
- [ ] Extract shared reflowable presentation (EPUB/FB2/text/Markdown/MOBI) and
  archive-image presentation (CBZ/CBR) behind focused app modules while retaining
  format-specific parsing and location types.
- [ ] Define stable locations for progress/bookmarks/search: page index for
  raster/archive formats and source/chapter plus text offset for reflowable ones.
  Confirm existing SQLite rows need no migration; add one only if unavoidable.
- [ ] Registry tests must prove each descriptor drives detection, import, dialog
  filters, opening, and library filter labels without another extension table.

** Gate 0 Acceptance

- [ ] PDF, EPUB, and CBZ behavior and database values are unchanged.
- [ ] Adding a test-only format requires one descriptor/adapter and one app
  opener, not edits to multiple extension matches.
- [ ] Unsupported files produce a user-facing error and never enter the library.
- [ ] Full existing core/app tests pass before any new format lands.

* Common Dependency and Fixture Gate

This gate applies separately to every work package; approval of one dependency
does not approve another.

- [ ] Record candidate versions, direct/transitive licenses, native library or
  executable requirements, source availability, target architectures, and Nix /
  distribution changes.  Reject GPL/AGPL or otherwise incompatible/restrictive
  choices unless project licensing policy is deliberately changed first.
- [ ] Confirm parser/decoder maintenance and fuzz/security posture.  Define input,
  decompression, image-dimension, allocation, nesting, and page-count limits.
- [ ] Create minimal, feature-rich, malformed, truncated, and oversized-limit
  fixtures under ~crates/shosai-core/tests/fixtures/~.  Generate fixtures in-tree
  where practical; otherwise record provenance and redistribution permission.
- [ ] Keep parsing/decoding off the UI executor and use cancellation/bounded caches
  for expensive page/image work.

- [ ] License review and package smoke tests pass on every supported target.

* Cross-Cutting Files Likely Touched

- Core: ~crates/shosai-core/src/lib.rs~, new ~format.rs~ and format modules,
  ~library.rs~, ~document.rs~ only where raster reuse requires it, shared
  reflowable/archive-image modules, ~search.rs~, and ~crates/shosai-core/Cargo.toml~.
- App: ~crates/shosai-app/src/app.rs~, new reader/opening modules under
  ~crates/shosai-app/src/~, and ~crates/shosai-app/Cargo.toml~ only when needed.
- Tests: new per-format integration tests beside existing
  ~crates/shosai-core/tests/*_tests.rs~, fixtures under ~tests/fixtures~, and app
  unit tests for factory/reader/location behavior.
- Packaging: ~flake.nix~, ~flake.lock~, and files under ~packaging/~ only after a
  dependency gate proves native/runtime changes are necessary.

* Release Acceptance Criteria

- [ ] Gate 0 is merged and existing formats have no regression.
- [ ] Each enabled format independently passes its dependency/license, fixture,
  security-limit, import, open, cover, reader, progress, and search criteria.
- [ ] Supported extensions and library filters come from one registry; format
  errors identify unsupported, corrupt, encrypted, or missing-runtime cases.
- [ ] Full workspace tests, Nix build, and supported-platform package smoke tests
  pass; notices and user-facing supported-subset documentation are updated.

* Risks and Mitigations

- Parser/decoder vulnerabilities: use maintained libraries, strict bounds,
  background work, fuzz targets where practical, and malformed fixtures.
- Native dependencies reduce portability: make platform/package validation a
  pre-implementation gate and defer formats without supportable binaries.
- A universal abstraction can erase format semantics: share detection, import,
  locations, and presentation by capability while retaining format-specific APIs.
- Extension-only detection can misclassify files: use bounded signatures where
  reliable and report ambiguity rather than trying every expensive parser.
- Saved locations may drift after parser changes: store logical anchors/offsets,
  version location payloads if introduced, and test restoration across reopen.

* Explicit Non-Goals

- DRM removal, key discovery, decryption, bypass instructions, or integration
  with circumvention tools for MOBI/AZW/AZW3 or any other format.
- Dynamic third-party plugins, a stable plugin ABI, or out-of-process converters.
- Writing/converting/exporting these formats, cloud acquisition, or catalog
  download support.
- RAR creation, multipart repair, password prompts, or accepting restrictive
  ~unrar~ licensing merely to claim CBR support.
- Full HTML/browser behavior in Markdown, FB2, or Kindle content; remote resources
  and active content remain blocked.
