= RFD 3 Cloud synchronization

== Goal

Synchronize reading progress and bookmarks across installations while preserving
offline-first local reading and keeping credentials out of SQLite, logs,
diagnostics, and payloads.

== Proposal

Introduce portable book and record identities before transport and define
deterministic revisions, conflicts, deletions, and tombstone retention with test
vectors. Shōsai is unreleased, so the development SQLite schema may be replaced
instead of preserving path-keyed compatibility. Synchronization remains outside
the open/read critical path and applies remote changes transactionally.

A narrow transport interface provides conditional reads and writes, capability
validation, bounded payloads, cancellation, and typed failures. WebDAV is the
first candidate, not a permanent choice absent evidence. Credentials use the OS
credential store; book files and cover blobs are initially out of scope.

Identity, protocol, conflict, transport, and privacy decisions must converge
before implementation commits to a wire format or provider.

Flutter presents sync state and supplies platform credential, connectivity, and
background-scheduling adapters under RFD 4. The core may emit privacy-safe typed
notification intents for actionable sync failures. Push delivery is not a sync
transport, must not be required for convergence, and is deferred until a
server-originated event justifies APNs, FCM, or web-push infrastructure.
