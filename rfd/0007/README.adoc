= RFD 7 MVP: one reading experience across formats and devices

== Goal

Define the minimum product Shōsai ships first: a reader that gives the same
reading experience regardless of medium. A person reads, marks up, searches,
and follows references the same way in an EPUB or a PDF, on a desktop, a
tablet, or a phone.

The current application is historical reference for this RFD, not its
baseline. Where the current behavior disagrees with the outcomes below, the
outcomes win, and replacing the current frontend outright is acceptable.

== Design mock

An interactive mock accompanies this RFD on the project design canvas
(https://claude.ai/artifact/5BwNtruvTADWsgZHzJ5XiS[Shosai design canvas],
"MVP" row). It has four boards: the outcomes summarized here, and one working
prototype laid out for desktop (1440 × 900), tablet (1180 × 820), and phone
(390 × 844). The prototype uses public-domain text from _On the Origin of
Species_ (EPUB), Shannon's _A Mathematical Theory of Communication_ (PDF), and
_吾輩は猫である_ (EPUB, vertical text).

The mock is the reference for layout and interaction. It is not a visual
specification: typography and colors reuse the existing tokens and
link:../../docs/typography.md[typography rules] and can change in
implementation review.

== Outcomes

=== 1. Every device

Shōsai runs on desktop, tablet, and phone from one Flutter application
(link:../0004/README.adoc[RFD 4]). The page, gestures, and controls are the
same everywhere; only their arrangement adapts to the window:

[cols="1,1,1,1",options="header"]
|===
|Surface |Desktop |Tablet |Phone

|Open books
|Tab strip with a pinned library tab
|Tab strip with a pinned library tab
|Tab switcher behind a count button

|Notes
|Panel docked beside the page
|Panel sliding over the page
|Bottom sheet

|Reference peek
|Card above the progress bar
|Card above the progress bar
|Bottom sheet

|Search
|Palette over the window
|Palette over the window
|Full screen
|===

*Done when* the same library, tabs, notes, and search work on Linux, macOS,
Windows, iPad, Android tablets, iPhone, and Android phones.

=== 2. Any medium

EPUB and PDF share one reader. The format appears only as a small badge on
tabs, library entries, and search results; it never changes which controls
exist or where they are.

* *Location.* Every position reads as a section label, a percentage, and a
  page number. EPUB page numbers depend on the current layout; PDF page numbers
  are fixed.
* *Progress.* One progress bar and one location line in the same place.
* *Appearance.* One theme set (paper, sepia, night) applies to both formats. A
  PDF in night theme is shown with inverted luminance; its layout never changes.
* *Size.* One control sets text size for EPUB and zoom for PDF, labeled for
  what it does in the current book.
* *Pages.* One setting chooses one or two pages for both formats, defaulting
  to two.
* *Selection and highlights.* One selection and highlight model, as defined by
  link:../0006/README.adoc[RFD 6].
* *The book keeps its voice.* EPUB fonts and writing direction, including
  vertical Japanese text, are honored. PDF pages keep their appearance.

*Done when* every reader action in the mock behaves the same for an EPUB and a
PDF.

=== 3. Notes and annotations, findable anywhere

There are three kinds of note, all stored and listed the same way:

[cols="1,2,2",options="header"]
|===
|Kind |Attached to |Example

|Highlight
|A text range, with a color and an optional note
|A sentence in a chapter or on a PDF page

|Page note
|A location: an EPUB position or a PDF page
|"Fig. 1 is the model every later section refers back to."

|Book note
|The whole book
|"Reading group pick. Chapters III and IV first."
|===

A single notes surface lists notes for _this book_ or _all books_. Choosing a
note opens its book, in a tab, at its anchor.

Search is available from every screen, including the library. One query covers
book text and notes across every book in the library, and results group notes
before book text. Choosing a result opens the book at the match.

*Done when* a note written in one book is found from any tab and opens at its
exact place.

=== 4. Many books in tabs

Each tab holds one book and its current position. The library is the pinned
first tab and the place new tabs open from. Opening a book that already has a
tab focuses that tab instead of opening a second one. Open tabs and their
positions are restored when the application starts again. The Iced frontend's
tab strip is the reference for desktop behavior.

*Done when* tabs open, switch, close, and come back after relaunch with their
positions kept.

=== 5. Jumpable references

Footnotes, cross-references, figure and table links, and contents entries are
links in both formats: EPUB hyperlinks and PDF link annotations or internal
destinations.

. Activating a reference opens a _peek_ with the target's label and a short
  preview, without leaving the page.
. *Go to* jumps to the target.
. Every jump records where it left from. A *Back* control returns there. Jumps
  from search results and notes record a return point too, including jumps
  into another tab.

Footnotes whose text is already in the peek need no jump.

*Done when* EPUB links and PDF link annotations both peek, jump, and return.

== Interaction rules

. *Format is metadata, not a mode.* No control exists for one format only.
  Where formats need different mechanics, the control keeps its place and
  meaning.
. *Peek before you jump, and always a way back.*
. *Everything you write is findable.* Notes are first-class search results.
. *Layout adapts, behavior does not.* Panels become sheets; outcomes stay
  the same.

== Out of scope for the MVP

* Synchronization between devices (link:../0003/README.adoc[RFD 3]). Notes
  stay on the device but use portable identities so synchronization can follow.
* Additional formats (link:../0002/README.adoc[RFD 2]).
* Writing highlights back into PDF files (RFD 6 interoperability phases).
* A web build, which RFD 4 keeps as a feasibility target.
* Collections or shelves beyond a single library list.
* CBZ comics, which the current application supports.

== Decisions

Recorded from owner review on 2026-10-14.

* *EPUB defaults to paginated reading.* Continuous scrolling may follow as an
  option but is not the default.
* *Two-page spreads are the default for EPUB and PDF.* Readers can switch
  between one and two pages. Spreads follow the book's page progression, so a
  right-to-left book places its first page on the right. Where two pages would
  not be readable side by side, such as a phone in portrait, the reader shows
  one page.
* *CBZ is not part of the MVP.* Revisit once there is a concrete need; the
  current CBZ support is reference only.
* *Tabs across devices is a possible follow-up to RFD 3*, decided by how much
  complexity it adds to synchronization. Tabs are per device in the MVP.
* *Phone PDFs show fit-width pages, not a reflowed text view.* Pages are
  re-rendered at the current zoom and display density, so text never shows as
  an enlarged bitmap. A reflowed view may follow after the MVP.
* *EPUB writing direction is honored with no override.* The direction comes
  from the book: the spine's `page-progression-direction` and the content's CSS
  `writing-mode` (including the `-epub-writing-mode` alias). A book that
  declares neither reads horizontally, left to right. Readers cannot force a
  horizontal layout in the MVP.

== Relationship to other RFDs

* link:../0004/README.adoc[RFD 4] owns the Flutter frontend, platform targets,
  and the retirement of the Iced reference frontend. This RFD defines what that
  frontend must deliver first.
* link:../0006/README.adoc[RFD 6] owns selection, highlight anchors, and their

  of that model.
* link:../0003/README.adoc[RFD 3] and link:../0002/README.adoc[RFD 2] are
  explicitly after the MVP.
